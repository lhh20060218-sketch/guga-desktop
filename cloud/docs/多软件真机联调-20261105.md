## 三、三个必须修的缺陷（都已修，都已真机验证）

### P0-1　软件关窗口后进程还在，窗口变隐藏 → 误报"软件没开"

**现象**：用户说"装好了登录好了"，但 `pygetwindow` 一个都找不到。只有元宝一个 16×16 的 `com.tencent.yuanbao-siw` 和智谱一个 600×600 的 `floatBallWindow`。

**根因**：点右上角关闭后进程仍在跑，窗口只是变成隐藏态。而 `gw.getAllWindows()` **只枚举可见窗口**。用 ctypes 枚举全部句柄后，四款主窗口都在：

```
元宝      1216x839   隐藏
Kimi      1216x808   隐藏
智谱清言   1330x750   隐藏
豆包      1200x800   隐藏   ← 连豆包也一直藏在托盘里
```

**修法**：`_wake_from_tray()` —— 找标题匹配、尺寸 >300、排除 `floatBall/launcher/-siw/crashhandler/toolbar` 这些噪声窗，`ShowWindow(SW_RESTORE)` 叫回来。
找不到可见窗口时先叫回再找，不急着报"软件没开"。

**验证：4/4 全部唤醒成功**，其中包括一直被认为是"手动开着"的豆包。

### P0-2　窗口重叠时截图抓到**别人的界面**（最危险）

**现象**：明明写的是 `0_腾讯元宝.png`，打开一看是 **Kimi 的 KIMI 界面**（还带着"登录者1282"）。

**根因**：元宝在 `(352,104) 1216x839`，Kimi 在 `(352,120) 1216x808` —— 两个窗口几乎完全重叠。
截图是"抓屏幕上那块矩形"，**谁在上面就抓谁**。而 `find_window` 找到窗口 ≠ 它在前台。

这个 bug 的后果比"找不到窗口"严重得多：视觉定位会拿别人的界面去判定，然后按别人的坐标去点。

**修法**：`focus_window()` —— 找到窗口后强制抬到最前并**校验 `GetForegroundWindow()` 确实等于目标句柄**。

实现上踩了个坑：最初用 `ShowWindow(SW_RESTORE)` + `AttachThreadInput` 那套，**完全失效**（4/4 全失败，前台一直停在 Kimi，每次耗时 4 秒）。
根因是 Windows 的前台锁定：后台进程硬切 `SetForegroundWindow` 会被静默拒绝。
最后有效的招是 **按一下 Alt 伪造用户输入，再 SetForegroundWindow**：

```python
u.keybd_event(VK_MENU, 0, 0, 0)          # 按下 Alt
u.SetForegroundWindow(hwnd)               # 这时候门是开的
u.keybd_event(VK_MENU, 0, KEYEVENTF_KEYUP, 0)
```

**验证：4/4 一次成功，每款 0.4 秒**（失败时是 4 秒）。截图内容逐张肉眼确认全部正确。

### P1-3　元宝有升级推广弹窗，会挡住对话区

实测截图里，元宝主界面正中间盖着一个 **「Hy4 解锁更强生产力 / 开始使用」** 的弹窗，对话区被完全遮住，左下角还有"新版本就绪 / 重启升级"。

这会让视觉定位拿到一张"中间有大弹窗"的图，判断"输入框在哪"必然出错。
**处置**：`new_chat`/`click_input` 之前先做一次"有没有挡住的弹窗，有就点右上角 × 或'开始使用'"。待实现。

## 五、截图边界有 1–8px 外溢（待处理）

四张截图左边缘都能看到**上一个窗口的像素**透进来（Kimi 图左侧有元宝侧栏残影，智谱图左下角有"元宝1282"残影）。

原因：`GetWindowRect` 返回的矩形**包含 DWM 窗口阴影**。
影响：视觉定位可能被边缘杂像素干扰；点击坐标按此换算会有几像素系统偏差（这个量级一般不影响点击，但影响"像素差异校验"的准确性）。

**处置建议**：改用 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` 拿不含阴影的真实边界。
优先级 P2——不影响能不能用，影响精度。

## 六、视觉通道 401 的真相

裸脚本调用 `locate()` 报 `HTTP Error 401: Unauthorized`，**不是产品坏了**：

`guga_executor.TOKEN` 默认是空字符串，由 `guga_agent` 在配对成功后注入（`dex.TOKEN = token`）。
服务端 `/api/agent/vision` 挂了 `agentAuth` 中间件，没 token 必然 401。

**要验证视觉 + 喂文件，必须先配对**：
1. 网页登录 → 生成配对码（10 分钟内有效）
2. 本机跑 `guga_agent` 用配对码换取 token
3. 之后 `locate/see` 才可用

另外服务端还有个隐性依赖：`llmCfg.baseUrl && llmCfg.apiKey` 任一为空会返回「视觉模型未配置」（这是 HTTP 200 的正常返回，不是报错）。
