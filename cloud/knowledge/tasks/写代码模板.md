# 任务模板：写代码

## 目标示例
少爷：写个 Python 脚本，每天早上 9 点把昨天的销售 CSV 自动汇总成一张表发我邮箱，别让我手动跑。

## 子任务拆解

### 1. 需求拆解
- **执行方类型**：DeepSeek
- **一句话验收标准**：输出需求清单——输入路径（哪个目录读 CSV）、汇总口径（按区域求和）、邮件收件人、失败重试策略（重试 3 次后报警），少爷确认。

### 2. 代码实现
- **执行方类型**：Cursor
- **一句话验收标准**：在指定仓库生成脚本，含类型注解、异常捕获、日志打印，本地 `python xxx.py` 一次性跑通，无语法错误。

### 3. 测试验证
- **执行方类型**：Cursor + Claude（代码审查）
- **一句话验收标准**：用一份样例 CSV 跑通，输出的汇总数字与手算结果一致；再故意塞一条脏数据（缺列/格式错）验证容错不崩溃。

### 4. 交付说明
- **执行方类型**：咕嘎
- **一句话验收标准**：输出 README——部署路径、Windows 任务计划或 cron 的具体配置命令、3 条常见报错的排查方法，少爷照着 README 能在另一台机器跑起来。

## 预计顺序
1. **需求拆解**（串行前置）——需求不清写出来的代码必返工。
2. **代码实现**（依赖 1，串行）——按需求清单写。
3. **测试验证**（依赖 2，串行）——测试对象是刚写出来的代码。
4. **交付说明**（依赖 3 测试通过，串行收尾）——没测过的代码不配写 README。
