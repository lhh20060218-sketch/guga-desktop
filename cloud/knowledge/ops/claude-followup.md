# claude-followup：Claude（网页版）同一会话追问

- **剧本ID**：claude-followup
- **软件**：Claude 网页版（https://claude.ai/，本机未装桌面端，以网页版为准）
- **动作目标**：在上一条回答的上下文里继续追问，让 Claude 基于刚才那一轮补答、改写或深入展开，而不是把追问当成全新问题重答

## 前置条件
1. 已按 claude-ask 跑通至少一轮，当前会话里有一条完整的用户提问 + 一条 Claude 完整回答。
2. 页面停在该会话内：左侧历史列表中本条会话为高亮选中态，对话区能看到上一答。
3. 输入框为空、可键入；上一轮的中断按钮（停止生成）已经消失，说明没有还在跑的流。

## 步骤序列
1. **元素特征**：底部聊天输入框（composer，位置与 claude-ask 同）。
   **动作**：直接单击输入框，键入追问内容；不要点左下角「+」，否则另起新会话会丢掉上下文。
   **等待判据**：文字逐字上屏；输入框右侧提交按钮由灰转亮。
2. **元素特征（可选）**：输入框下方的模型名（Opus / Sonnet / Haiku）。
   **动作**：若追问是基于上一答做推理、验算、排错，保持和上一轮同一个模型，别中途切，免得口径跳变；润色、缩写类追问可临时降到 Haiku 提速。
   **等待判据**：模型名与上一轮一致，或符合本步意图。
3. **元素特征**：提交按钮（发送箭头图标，待真机核对）或回车。
   **动作**：点击提交（或 Enter）。
   **等待判据**：新的用户消息气泡接在上一条回答正下方，回答区重新开始流式输出。
4. **元素特征**：回答区正文。
   **动作**：等待输出跑完，期间不滚动太远、不点左侧别的会话。
   **等待判据**：流式文字停止，底部操作图标行重新出现。

## 成功判据
新回答接在旧回答正下方，且内容明显承接上一轮上下文——例如指代「刚才那个方案 / 你上一条说的」，或针对上一答的某一点展开、修正、缩写，而不是另起炉灶从头答一遍。

## 异常处理
- **它没接住上下文、当新题重答**：少爷，它把追问当成新问题了。咕嘎在追问前补上明确指代，改成「接着你上面第 2 点，……」或「针对刚才那个结论，……」再发一次。
- **追问太长、它只回半截**：少爷，这问太长被截了。咕嘎把追问拆短、一次只问一个点，或显式限定「只用 3 条要点回答」。
- **连追几轮后开始「失忆」**：少爷，Claude 多轮后细节会糊。咕嘎先用 claude-export 把当前结论复制留底，再开「新会话」把结论 + 新诉求一次性贴进去重问，比硬追更稳。
- **生成中途又断**：少爷，又答一半断了。咕嘎补一句「请接着上面继续」。
- **误点了左下角「+」导致上下文丢了**：别在新会话里硬撑。左侧历史列表按上一轮关键词找到旧会话点回去；新会话里那条孤问，悬停会话条目 → 删除（菜单原文待真机核对）。
- **回答越追越啰嗦、跑题**：在追问里显式收口，如「不要展开背景」「只要结论」。
