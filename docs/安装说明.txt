咕嘎（GUGA）桌面智能管家 · 安装与首次使用说明
================================================================

这份文档写给第一次拿到压缩包的人。不需要安装 Python、Node、数据库，也不需要命令行。

----------------------------------------------------------------
一、压缩包里有什么
----------------------------------------------------------------

GUGA-Desktop\                 程序目录（双击里面的 GUGA-Desktop.exe 启动）
使用说明.html                 完整图文说明（双击用浏览器打开）
使用说明.txt                  同样内容的纯文本版（没有浏览器关联时看这个）
安装说明.txt                  本文件：从解压到第一次用起来
作品介绍.txt                  这个作品是什么、能做什么、怎么做的

注意：不要只把 GUGA-Desktop.exe 单独拷出来运行；它必须和同目录的 _internal\ 在一起。

----------------------------------------------------------------
二、解压到可写目录（推荐）
----------------------------------------------------------------

1. 把 zip 解压到可写目录，例如 D:\GUGA。
2. 解压后应当是：GUGA-Desktop.exe 与 _internal\ 同级。
3. 只读目录（共享盘、Program Files）也能启动：配置和运行数据会写到用户目录，
   不会写安装目录；但为了导出交付物方便，仍建议放在可写目录。

如果解压后提示缺少 VCRUNTIME140.dll / 界面模块：
  说明解压不完整或被杀毒软件拦截，请重新完整解压整个压缩包，并把目录加入白名单。
  运行库已随包内置，不需要另装 VC++ Redist。

----------------------------------------------------------------
三、首次启动：先看自检
----------------------------------------------------------------

双击 GUGA-Desktop.exe，会先弹出启动自检窗，共 27 项。每一项都真调用一次被检能力
（不是只看文件在不在），拿到真实返回值或真实异常才算测过：

  实测通过（绿色）  该项真实返回值正常
  未测（灰色）      本机条件不具备（例如目标软件没运行），界面明确写“未测”，
                    不会因为文件/注册表存在就显示“通过”
  降级（黄色）      能用但有损；写清影响，例如“系统 OCR 不可用，豆包派单会降级”
  失败（红色）      写清缺什么 + 去哪补 + 补完要不要重启

任一降级/失败项行内都有「重试」按钮，点它只重测这一项，不用整体重启。
首次启动常见黄色：屏幕缩放不是 100%、没有 API Key、长路径未开启。
这不影响启动。勾选「以后不再提示」会记住选择；想恢复就删掉：
  %LOCALAPPDATA%\GUGA\runtime\install_suggestions.json

自检里的「系统 OCR（-File + 真识别中文）」会真的执行随包
tools\windows_ocr.ps1，生成一张中文图并识别，按字符重合率 ≥90% 判通过；
同时显示当前 PowerShell 执行策略。OCR 不可用只判“降级”，不判致命：
豆包派单会自动降级走 UIA + 剪贴板，不会中断复合任务。

自检窗底部还有「连接器 / 接入状态」入口，随时能查看各软件有没有真的接上。
出现红色致命项时，点「退出」会真的退出程序，不会带着致命问题硬进桌宠；
补齐环境后重新双击即可。

----------------------------------------------------------------
四、填 API Key 并测试连接
----------------------------------------------------------------

自检关掉后会自动进入「首次配置向导」：

1. 平台：下拉选 智谱 GLM / DeepSeek / 通义千问 / 自定义。
2. 接口地址和模型名会自动填好；自定义才需要手填。
3. 填 API Key，点「测试连接」。必须是真实请求成功（绿勾）再保存。
   没选服务商（接口地址为空）时，咕嘎不会向任何默认地址发请求，
   而是直接提示「未选择服务商」，避免把你的 Key 发给你没选的服务商。
   主模型不支持看图时：保存后右键 →「⚙️ 模型设置 → 视觉模型」，单独填
   vision_base_url / vision_api_key / vision_model；三项留空表示跟随主模型。
   只配一个多模态模型（如 qwen3-vl-plus）时，对话、拆解、截图理解都走它，无需分开填。
4. 云端大脑（可选）：不填也能用本地功能；填了才有管家派单/跨设备。
5. 点「保存并生效」。

包里不带 Key：压缩包内只有 ai_config.example.json 模板，没有 ai_config.json；
程序里也没有任何内置、试用或赠送的 Key 与端点。

不填 Key 也可以点「仍要保存」进入桌宠，但界面上会常驻一行红字
「未配置模型：对话 / 完整对话 / 截图分析不可用」，点它给出可照做的提示，
不会几秒就消失，也不会假装成功。之后右键桌宠 →「⚙️ 模型设置」随时补填。
请分清两件事：接入 MCP 只让咕嘎知道软件装在哪，不等于模型可用；
模型 Key 必须你自己在本机填。

配置保存位置（真实落点）：
  %LOCALAPPDATA%\GUGA\ai_config.json

旧版本放在安装目录（_internal\ai_config.json 或 exe 同级）的配置：
本版不再自动复制。启动时弹窗打码显示服务商、端点与 Key 后四位，
默认按钮是「重新填写（推荐）」；只有明确点「沿用这份配置」才会写入，
并记为「从旧配置继承」。选「重新填写」不会写入任何 Key。
「模型设置」页会显示 Key 来源：本机填写 / 从旧配置继承 / 云端下发。

----------------------------------------------------------------
五、进入桌宠与派单
----------------------------------------------------------------

保存成功后桌宠出现。右键桌宠打开菜单：
  - 对话：普通聊天，用你配置的模型
  - 模型设置：换模型/端点/Key，测连接
  - 派单给外部工具：在对话里点名，例如
      「用豆包写一篇 200 字作文」
      「用 WorkBuddy 问一句：用一句话介绍你能做什么」
      「用 JoyCode 把当前工程的编译错误修一下」

点名后不会由咕嘎的模型代写，而是真的去操作对应软件并核对回执。
JoyCode 需要提前打开目标工程和右侧 AI 面板；识别不到工程时会弹窗让你选一次。

云端账号的授权隔离（服务端已上线，桌面端按响应处理）：
  403 + CLOUD_NOT_ENTITLED        云端服务未开通 → 提示单独购买云端账号
  403 + CLOUD_QUOTA_EXCEEDED      云端额度用完 → 提示续费或等重置
  403 + ADMIN_ONLY                仅管理员可用 → 提示换管理员账号/找管理员开通
  403 + BASEURL_REQUIRES_NEW_KEY  换服务商后旧 Key 失效 → 去「模型设置」重填 Key
  这些 403 都按业务拒绝处理：不重试、不当网络波动、不用运营方凭据兜底。
  云端辅助（视觉 / 请示）的精确规则：HTTP 403 且 body.degraded=true 才降级。
  helper=vision 跳过本步截图理解，走本地启发式；helper=consult 等价于
  服务端兜底 deliverable，当前回复继续交付。任务仍然完成，不整单失败。
  提示文案：CLOUD_NOT_ENTITLED → “云端辅助未开通，已用本地模式继续”；
           CLOUD_QUOTA_EXCEEDED → “云端额度用完，已用本地模式继续”。
  日志记录 helper / code / 时间；code 只用于提示，不写进任务状态或失败原因。
  本地没填自己的模型 Key 时，本地对话明确不可用；云端功能也只在买了云端账号后可用，
  两者互不顶替。

----------------------------------------------------------------
六、让软件自报安装路径（MCP，一次配置长期有效）
----------------------------------------------------------------

别人的电脑把软件装在哪，无法穷举。所以本版让软件自己告诉咕嘎：

  发现：软件连上咕嘎的 MCP 服务后，调用一次 report_app 自报 exe 绝对路径
  指挥：仍然是界面自动化（UIA + 视觉 + 键鼠），不会改成走 MCP 派单

自检通过后，如果发现某款软件「已安装但没接入」，咕嘎会主动弹
「咕嘎 · 软件接入提醒」；点「现在接入（推荐）」就打开接入窗口。
同一天同一批软件只提醒一次。永久入口有三个，随时能进：
  桌宠右键 →「🔌 连接器 / 接入状态（MCP）」
  桌宠右上角「接入」按钮
  启动自检窗底部「连接器 / 接入状态」

接入状态面板每款软件一行，统一三态：
  已检测到配置 / 界面已显示 guga（或官方提示添加成功）/ 未验证
只有点「验证连接」真实握手拿到 5 个工具，面板才显示“已连接”；
其余任何情况都不会写“已接入”。
面板可以随时「重新检测」刷新，不只在启动时算一次。

每行都有「验证连接」：按该软件的配置真实拉起一次
  GUGA-Desktop.exe --guga-mcp
然后列出工具清单（应为 5 个，含 report_app），并显示最近一次 report_app
自报的路径与时间。失败会直接写明原因：配置路径不对 / exe 不存在 /
超时 / 工具清单不符。

「新增软件」入口：填软件名称 + 可执行文件路径（可点「浏览…」选文件），
咕嘎生成对应配置并可一键复制，同时把该软件的自报路径写进
app_reports.json，下次直接从这里启动。

1. 在接入窗口里，每款已安装软件旁边都有「复制配置」。
   点一下会把配置写进剪贴板并读回校验，成功时按钮变成「已复制」，
   旁边写明“粘贴到：哪里”。剪贴板被别的程序占用时，会弹出已全选的文本框，
   按 Ctrl+C 手动复制即可。
2. WorkBuddy（路径与入口已按 2026-11-08 官方文档 + app.asar + 真机点界面三重核对）：
   配置落点就是 %USERPROFILE%\.workbuddy\mcp.json，官方文档写明、app.asar 的
   getMcpConfigPath() 也返回这个路径。
   · 界面入口（V5.9.3）：侧边栏「专家·技能·连接器」→ 连接器页右上角铅笔图标 →
     「MCP 服务管理」→「＋添加 MCP」。它打开的就是同一个 mcp.json，界面保存立即生效。
   · 直接改文件：改完必须完全退出 WorkBuddy（托盘退出；关窗口无效）再重启，列表才刷新。
   · 首次连接必须在「MCP 服务管理 → 我的 MCP」里点「信任」；不点显示灰色、工具不启用。
     之后改 command / args / env 会让信任记录失效，需要重新点一次信任。
   · command 不要指向 %TEMP% 解压目录（临时目录被清后失效，路径变化还会让信任作废）；
     先把咕嘎解压到固定目录（如 D:\GUGA），再生成配置。
   粘贴复制的配置 → 保存 → 按上面两条（信任 / 完全退出重启）生效。
3. JoyCode：官方只有界面入口「MCP市场 → 全局配置文件 → +MCP配置」，
   没有公布配置文件路径。本版**不再往 {workspace}/.joycode/mcp.json 写文件**，
   只生成可粘贴 JSON（本地程序必须含 "type": "stdio"），引导你走官方界面。
   保存后以右下角「添加成功，正在更新」为准；官方未要求重启。
4. 豆包：官方入口是「插件·技能·伙伴 → 插件 → 右上角 + 添加 →
   新建自定义连接器」。g 版起首选 HTTP：
   服务器名称 guga、传输类型 HTTP、服务器 URL http://127.0.0.1:<实际端口>/mcp、
   Headers 留空；端点不可用时，卡片同一份文本里带 STDIO 备选
   （传输类型 STDIO + 运行命令 / 参数 / 环境变量）。
   咕嘎主程序启动时会自动开本机 HTTP 端点：只绑 127.0.0.1，路径 /mcp，
   端口从 18760 起、被占用就 +1；实际端口显示在接入面板豆包卡片上，
   也写在 %LOCALAPPDATA%\GUGA\runtime\mcp_http.json。
   单独排查端点：GUGA-Desktop.exe --guga-mcp-http；
   关闭端点：ai_config.json 里写 "mcp_http_enabled": false 或环境变量 GUGA_MCP_HTTP=0。
   该连接器只在豆包「工作」模式生效，对话模式和 /、@ 都搜不到；
   官方未要求重启，也没有独立的工具清单页面，只能看「插件 → 管理」。
   豆包状态按三态显示：已检测到配置 / 界面已显示 guga / 未验证。
   随包根目录另有 豆包连接器配置教程.txt，按里面的步骤做。
5. 回到咕嘎点「验证连接」，确认真实握手拿到 5 个工具：
     report_app / get_task / report_progress / submit_artifact / ask_guga
   新接入只需要 report_app；另外 4 个是旧工作流的兼容通道，咕嘎派单不调用它们。
6. 让软件调用 report_app，参数填软件标识、名称、exe 绝对路径、版本、能力。
   咕嘎把它写进 %LOCALAPPDATA%\GUGA\app_reports.json（原子写 + 回读校验）。
   之后启动直接按这条路径走，不用再猜；升级或换目录后再报一次即可覆盖。

重要：复制出来的配置里没有、也不会有模型 API Key，只有本地命令和参数；
也不依赖 Python，不会出现开发机的解释器或源码路径。
模型 Key 只由你在咕嘎首次配置里自己填，不随包分发、不内置；
豆包连接器的「自定义 Headers」留空，不要填 Key。

配置形状（command 按你解压后的位置自动生成，指向 GUGA-Desktop.exe，args 固定 --guga-mcp）：

  {
    "mcpServers": {
      "guga": {
        "command": "D:\\GUGA\\GUGA-Desktop\\GUGA-Desktop.exe",
        "args": ["--guga-mcp"],
        "env": {"PYTHONIOENCODING": "utf-8", "GUGA_CLIENT_ID": "workbuddy"},
        "disabled": false
      }
    }
  }

豆包首选 HTTP 时不用 JSON，按表单逐栏填（卡片上的「复制连接器字段」就是这段）：
  服务器名称：guga
  传输类型：HTTP
  服务器 URL：http://127.0.0.1:<实际端口>/mcp   ← 以卡片上显示的真实端口为准
  Headers：留空

路径优先级：用户手动指定 > MCP 自报 > 常见目录/注册表/开始菜单/PATH 探测。
自报路径失效时只记一条原因并继续回退探测，不会因为一条脏记录就启动不了。

----------------------------------------------------------------
七、现场五条纪律（演示前必读）
----------------------------------------------------------------

1. 只开一个咕嘎实例。
   任务管理器里不要留 GUGA-Desktop.exe / guga-agent.exe，否则会抢单、顶号。

2. JoyCode 右侧 AI 面板要提前打开。
   冷启动时面板默认关闭；先打开目标工程，再打开右侧面板，然后派单。

3. 派单后 3 秒内别点别的窗口。
   咕嘎要把目标软件置前并模拟键鼠，抢焦点会让输入落到错误窗口。

4. 上一单产物弹框先关掉再派下一单。
   模态弹框挡在前面时，下一次派单的定位会失败。

5. 包里不带 Key，第一次必须先填。
   不填只能使用本地功能；现场演示前先完成「测试连接 → 保存」。

----------------------------------------------------------------
八、三种失败提示是什么意思
----------------------------------------------------------------

派单时可能看到三类失败提示，它们含义不同：

1）「本机没装 XXX，这次我不代写」
   含义：找不到该软件的 exe，也没有可用的启动协议。
   处理：按提示安装并登录；装好后再说一次「用 XXX …」。
   注意：这时咕嘎不会用自己的模型代写冒充，这是产品约束，不是故障。

2）「没能调起 XXX：没有真实工具调用回执」
   含义：软件装了，但窗口没拉起来/没拿到执行通道，任务没有真正执行。
   处理：手动打开并登录该软件，确认窗口能正常显示，再重试；
         仍失败就换一个工具，或把日志里的原因发给维护者。
   常见触发：豆包 launch_failed、WorkBuddy 窗口未响应、JoyCode 未登录。

3）「没有真实工具调用回执，不拿模型代写冒充」（交付闸）
   含义：执行过程中没有留下任何一次真实的工具成功回执，只有模型生成的文字。
   处理：这一单不可交付；检查目标窗口是否被切走、页面是否变了（WorkBuddy 会做
         页面归属校验，页面不一致会明确拒绝），然后重新派单。
   注意：看到这条说明系统在拦截“跳步”，不是漏做了功能。

另外，同一目标已有未完成任务时会被拦截，提示「同一目标已经在执行，这次不重复派单」；
等上一单结束或换目标即可。

----------------------------------------------------------------
九、常见拦截与处理
----------------------------------------------------------------

SmartScreen（Windows 已保护你的电脑）
  点「更多信息」→「仍要运行」。这是未签名程序的正常提示，不影响功能。

杀毒软件误报 / 解压后缺文件
  把整个解压目录加入白名单，重新完整解压；不要只拷 exe。

没有 Python 环境
  不需要。运行库、Python、依赖全部内置在程序目录里。

双击没反应
  先看 %LOCALAPPDATA%\GUGA\logs\startup.log 的最后几十行（设了 GUGA_HOME 时在 %GUGA_HOME%\logs\startup.log）；
  再确认是否已有旧实例在运行（只允许一个实例）。

测试连接失败
  按提示区分：Key 无效 / 额度不足 / 模型不存在 / 地址不存在 / 超时 / 网络不通；
  地址通常以 /v1 结尾，模型名要带平台版本号。
  若报 HTTP 405：先确认没把 /chat/completions 粘进地址；20261110l 起已改为
  “重定向后保留 POST 重发”，若仍 405，多半是系统代理拦截，可关闭代理或把
  模型域名加入 NO_PROXY 后重试（诊断里能看到代理快照与实际请求地址）。

缩放不是 100%
  界面指挥的点击定位可能偏移；演示前建议设置 → 系统 → 显示 → 缩放设为 100%。

----------------------------------------------------------------
十、配置与运行数据位置
----------------------------------------------------------------

对话配置（含 Key）   %LOCALAPPDATA%\GUGA\ai_config.json
运行数据             %LOCALAPPDATA%\GUGA\runtime\
交付物               %LOCALAPPDATA%\GUGA\deliverables\
软件自报路径(MCP)    %LOCALAPPDATA%\GUGA\app_reports.json
旧配置迁移选择记录     %LOCALAPPDATA%\GUGA\runtime\legacy_config_prompt.json
启动日志             %LOCALAPPDATA%\GUGA\logs\startup.log（设 GUGA_HOME 时在 %GUGA_HOME%\logs\）

迁移原则：安装目录里的旧 ai_config.json 只被“检测”，不会被自动复制；
选择“重新填写”会记在 legacy_config_prompt.json 里，之后不再反复弹窗。
ai_config.example.json 是模板，永远不参与迁移。

解析顺序：%GUGA_HOME% → %LOCALAPPDATA%\GUGA → %APPDATA%\GUGA →
          %USERPROFILE%\GUGA → 安装目录（仅前几处都不可写时才用）。

卸载：退出桌宠，删除解压目录即可；如需彻底清理，再删除上面两个用户目录。

----------------------------------------------------------------
十一、OCR 依赖与缺中文语言包怎么办
----------------------------------------------------------------

豆包等软件的文字识别依赖 Windows 自带 OCR（Windows.Media.Ocr）。
g 版起 OCR 不再是硬依赖：读界面文本顺序为
  UIA（ValuePattern / TextPattern）→ 剪贴板回读 → OCR 兜底。
OCR 不可用时：
  · 自检把「系统 OCR」判为“降级”，写明缺什么/去哪补/补完是否重启；
  · 豆包派单自动降级继续，回执与证据标注 ocr_unavailable；
  · 失败码是 ocr_unavailable，不再出现 adapter_exception；
  · 复合任务不会因为 OCR 失败而中断。

缺中文 OCR 语言包的装法：
  设置 → 应用 → 可选功能 → 添加功能 → 搜索并安装
  “中文(简体) 光学字符识别”，装完重启咕嘎（不用重启电脑）。
装好后回启动自检，点 OCR 这一行的「重试」，应显示字符重合率 ≥90%。

如果自检显示“系统禁止运行 PowerShell 脚本”：
  以管理员身份运行 PowerShell，执行
    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
  或让 IT 把安装目录加入 AppLocker/杀软白名单，然后回自检点「重试」。
  注意：旧版事故就是“-Command 能建引擎、-File 被执行策略拦截”，
  g 版自检改为真执行 -File + 真识别，才能提前发现。

如果自检显示“Get-ExecutionPolicy 读取失败”：
  只是这台机器读不到执行策略（PowerShell 安全模块异常），
  真正的判定仍以 -File 真执行结果为准；不影响 OCR 通过/失败结论。

----------------------------------------------------------------
十二、出问题怎么导出诊断发给我们
----------------------------------------------------------------

入口有两个：
  桌宠右键菜单 →「🩺 导出诊断（发给我们）」
  右键 → 模型设置 → 页面里的「一键导出诊断」按钮

导出会在桌面生成一个 zip：咕嘎诊断_年月日_时分秒.zip，内含：
  · 自检逐项结果（通过/降级/失败/未测 + 真实返回值）
  · 最近 30 分钟日志 + 最近一次任务时段（含失败时段）的日志（startup / adapter_chain 等）
  · 最近一次任务的 result.json（强制带上，不受 30 分钟窗口限制）
  · 任务台账摘要
  · 失败码与证据目录清单
  · manifest.json：版本号、构建 SHA、导出时间、机器信息
    版本/构建 SHA/包内容摘要优先读包内固定位置 _internal\build-info.json；
    若桌面/下载目录/安装包同级仍能找到原始 zip，会实测其 SHA256 并对照同名
    .sha256 sidecar；找不到原始 zip 时如实标注来源，不拿旧值冒充。

脱敏：API Key、Authorization、Bearer、sk-*、长十六进制串都会替换为 ***；
ai_config.json 原文不会被打包。确认后再发给我们，zip 可直接附在消息里。

----------------------------------------------------------------
十三、不依赖真实模型 Key 的复验入口（i 版新增）
----------------------------------------------------------------

1) 跑 OCR 降级续跑（走真实 adapter_chain，两步都执行，第一步记为 degraded 后继续）：
     GUGA-Desktop.exe --simulate-adapter-failure ocr_degraded --simulate-out D:\降级.json
   结果 assertions 里 first_degraded / second_done / continued_after_ocr_failure 均为 true。

2) 跑失败码四段（可换任意失败码，如 adapter_exception / not_submitted）：
     GUGA-Desktop.exe --simulate-adapter-failure adapter_exception --simulate-out D:\四段.json
   结果 four_segment 固定四段：失败码 / 阶段 / 原始异常 / 下一步；
   assertions.four_sections 与 raw_not_placeholder 为 true。

3) 下载离线语音模型（不随包，约 40MB）：
     GUGA-Desktop.exe --download-vosk-model
   默认先走国内镜像 hf-mirror.com（实测 5.6MB/s、约 8 秒下完），
   校验 SHA256 后自动解压到 %GUGA_HOME%\models\vosk-model-cn；
   镜像失败自动回退 Vosk 官方源。每个源带 30 秒读超时，不会无限卡住。
   完成后再跑 --selfcheck-json，第 9 项才会从「未测」变为「通过」。
   桩适配器不联网、不读任何 Key；以上入口不需要真实模型配置。

----------------------------------------------------------------
十四、失败文案怎么读（g 版固定四段）
----------------------------------------------------------------

豆包 / WorkBuddy / JoyCode 失败时不再只说“（错误）”，固定给出四段：
  失败码：launcher_not_found / workspace_not_found / panel_not_open /
          typed_in_editor / not_submitted / artifact_incomplete /
          artifact_stale / login_required / window_blank / ocr_unavailable
  阶段：启动 / 定位工作区 / 提交指令 / 等待产物 / 校验交付
  原始异常或 stderr 摘要（限长、脱敏）
  下一步：具体到点哪个按钮或设置哪个环境变量
找不到归类时写“未归类：<异常类型>: <首行消息>”，绝不写“（错误）”占位。

----------------------------------------------------------------
十五、模型 401/403 与 Key 自检（20261110q）
----------------------------------------------------------------

1. Key 会被自动洗净：读取和保存时去掉 BOM、零宽字符和首尾空白；
   如果 Key 中间夹着空格或换行，会提示“中间含有空白或换行（清理后长度 N）”，
   并且这次不会发出请求。旧版配置迁移时也先洗净再落盘。

2. 失败文案末尾会带凭据指纹：
   本次凭据：长度 N · 前四 XXXX … 后四 XXXX · 来源 main/fallback/legacy
   拿它和之前能通的那份配置对比；四项完全一样仍 401，说明不是 Key 被换，
   更可能是服务商侧的权限、额度或风控变化。

3. 401/403 会分成三类给下一步：
   - Key 无效 / 未授权：核对 Key 是否完整、是否属于当前服务商；
   - 没有模型权限 / 模型不存在：核对模型 id，或换有权限的模型；
   - 额度或余额不足：到服务商控制台充值或确认免费额度。
   无法归类时显示“已打码、截断 240 字”的服务端原文，可直接发给开发者。

4. 验证按钮：右键桌宠 →「⚙️ 模型设置」→「验证 Key（直连/系统代理）」。
   两条链路各发一次真实请求，只显示模式、状态码、耗时和打码片段；
   两条结果不同时，提示代理可能是失败来源。

5. 云端账号入口常驻：右键桌宠 →「☁ 云端账号（可选）…」。
   不填不影响本地对话、打开软件、截图分析，只影响派单/跨设备；
   可先点「测试登录」再保存，保存后自动重新登录。

----------------------------------------------------------------
十六、自检不污染派单输入（20261110r）
----------------------------------------------------------------

1. 旧版（q 及更早）启动自检会给 Windows 的 SendInput 设一份全局类型签名，测完不还原；
   之后派单真正按键时会报：
   ArgumentError: argument 2: TypeError: expected LP_INPUT instance
   instead of pointer to _INPUT
   界面显示「第 1/2 步（豆包）失败：… 缺什么：adapter_exception」，第一步就中断。
   重启咕嘎不能绕过，必须换 20261110r 或更新的包。

2. 20261110r 起：
   - 自检的 sendinput 项改用独立的输入接口实例，不再碰全局签名；
   - 派单侧（快捷键发送、文字批量输入）每次调用 SendInput 前显式绑定自己的签名，
     即使同一进程里刚跑完自检也不会串味。

3. 判断版本：右键「导出诊断」，包版本为 20261110r、自检版本为 r-1。
   注意：自检通过只说明自检项本身通过，不等于派单链路一定可用。

----------------------------------------------------------------
十七、修复豆包 UIA 坐标 KeyError（20261110s）
----------------------------------------------------------------

1. 20261110r 及更早：豆包窗口 OCR 不可用、走 UIA 降级定位输入框时，界面显示
   「第 1/2 步（豆包）失败：KeyError: 2。缺什么：adapter_exception」，第一步约
   2~3 秒即中断。原因是 UIA 返回的输入框坐标是字典，旧代码按列表下标取值。
2. 20261110s 起：坐标同时兼容字典 / 列表 / 元组，字段缺失或尺寸为 0 按原逻辑跳过，
   不再抛 KeyError；不需要改豆包任何设置。
3. 新增失败码 ocr_empty：OCR 引擎可用但识别到 0 行 0 字时显示该码（阶段「等待产物」），
   与 adapter_exception 分开，便于一眼判断失败层次。
4. 判断版本：右键「导出诊断」，包版本应为 20261110s、自检版本 s-1。
