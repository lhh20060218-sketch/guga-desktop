# 咕嘎 · 评委安装与使用说明

> 面向第一次接触本作品的评委：不装 Python、不装 Node、不装数据库，解压双击就能看到桌宠。
> 每条限制都来自真机实测；本轮没跑通的能力会明确标出，不写成「理论上可行」。
>
> 本说明由构建流程随包生成：压缩包根目录同时提供 `使用说明.html` 和 `使用说明.txt`
> （没有浏览器关联时直接看 .txt）。包名与构建时间以压缩包文件名为准；
> 解压前可用 `Get-FileHash <包名>.zip -Algorithm SHA256` 核对完整性。

## 〇、现场五条纪律（演示前必读）

1. **只开一个咕嘎实例**：任务管理器里不要留 `GUGA-Desktop.exe` / `guga-agent.exe`，否则会抢单、顶号。
2. **JoyCode 右侧 AI 面板提前打开**：冷启动时面板默认关闭，咕嘎不会替你按快捷键；先打开目标工程和右侧面板。
3. **派单后 3 秒内别点别的窗口**：咕嘎要把目标软件置前并模拟键鼠，抢焦点会导致输入落到错误窗口。
4. **上一单产物弹框先关掉再派下一单**：模态弹框挡在前面时，下一次派单的定位会失败。
5. **包里不带 Key，第一次必须先填**：包内只有 `ai_config.example.json` 模板，没有 `ai_config.json`；不填只能使用本地功能。

## 三、安装步骤

1. **核对包**（推荐）：
   ```powershell
   Get-FileHash "GUGA-Desktop-<构建时间>-最终版.zip" -Algorithm SHA256
   ```
   把结果与发布时公布的 SHA256 对照即可（本说明在包内，无法写自身的哈希）。
2. **解压到可写目录**（如 `D:\GUGA`；只读目录也能启动，配置会写到用户目录）：
   - 解压后应当是：`GUGA-Desktop.exe` + `_internal\` 同级，压缩包根目录还有 `使用说明.html` / `使用说明.txt`。
   - **不要只把 exe 拷出来单独运行**。
3. **双击 `GUGA-Desktop.exe`**。

### SmartScreen / 杀毒软件提示怎么过

本作品**没有购买代码签名证书**，首次运行会出现蓝色提示：

- 「Windows 已保护你的电脑」→ **更多信息** → **仍要运行**。
- 「未知发布者」→ 同上，这是未签名程序的正常提示。
- 360 / 火绒 / Defender 报「未知程序修改键鼠」→ **允许**，或把整个目录加白名单。
  咕嘎确实会模拟鼠标键盘（这是「指挥别的 AI 软件」的实现方式），属预期行为。
- 若文件被直接删除：从压缩包重新解压，先加白名单再运行。

### 解压不完整会怎样

自检第 3 项会直接报**致命**：`安装包缺少运行库文件` / `缺少界面必需模块`（常见于被杀软拦了部分文件）。
重新解压即可，不需要单独装 VC++。

## 四、首次配置（API Key 放哪）

包内**不带** `ai_config.json`，所以第一次启动一定走配置流程：
**启动自检 → 建议安装 → 首次配置向导 → 桌宠**。

### 方式 A：跟着向导走（推荐）

向导标题「咕嘎 · 首次配置向导」，首行提示「三步让咕嘎跑起来：① 选平台填 Key ②（可选）填云端账号 ③ 保存」。

1. **平台**下拉：`智谱 GLM（推荐：有免费额度，注册最快）` / `DeepSeek 官方` / `通义千问（阿里）` / `自定义`。选前三项会自动填「接口地址」「模型名」。
2. 点「申请 Key」打开对应平台注册页，登录后创建 API Key 并复制。
3. 粘贴到 **API Key**（占位「粘贴你的 API Key（形如 sk-…）」），点 **测试连接**。
   - 真实打一次接口，最长等 25 秒；通过后才允许继续。
4. **云端监工段可留空**：不填账号密码就没有「派个任务…」「任务台账」，桌宠本体照常跑。
5. 点 **保存并启动咕嘎**。保存时回读校验，写入用户可写目录。

### 方式 B：手写配置文件（可选）

```
%LOCALAPPDATA%\GUGA\ai_config.json
```

最少三项：

```json
{
  "api_key": "你的对话 API Key",
  "base_url": "https://open.bigmodel.cn/api/paas/v4",
  "model": "glm-4-flash"
}
```

> 旧版本放在安装目录（`_internal\ai_config.json` 或 exe 同级）的配置**不再自动复制**。
> 启动时会弹窗打码显示服务商、端点与 Key 后四位，默认按钮是「重新填写（推荐）」；
> 只有你明确点「沿用这份配置」才写入用户目录，并记为「从旧配置继承」。
> 选「重新填写」不会写入任何 Key。模板 `ai_config.example.json` 永远不参与迁移。
> 安装目录只读时也能保存（交付前已在只读安装目录实测）。

可选段落：

| 字段 | 用途 | 不填的后果 |
| --- | --- | --- |
| `vision_base_url` + `vision_api_key` + `vision_model` | 单独指定视觉模型（主模型不支持看图时）；三项留空则跟随主模型 | 截图分析不可用，其余不受影响 |
| `zhipu_api_key` + `vision_model`（旧写法） | 智谱视觉模型看屏幕 | 截图分析不可用，其余不受影响 |
| `cloud`（`base_url`/`username`/`password`） | 云端监工：派单、台账、验收播报、跨设备 | 菜单里不出现派单/台账，桌宠本体正常 |
| `realtime_voice` | 千问实时语音 | 只有「按住说话」+ 系统 TTS |

**`base_url` 怎么填（20261110l 起自带自救文案）**

`base_url` 必须是 **OpenAI 兼容接口的根地址**，形如 `https://.../v1`。咕嘎会自己在末尾拼
`/chat/completions`，所以你**不要再把 `/chat/completions` 粘进去**（粘了会自动还原，
设置页会显示「已自动校正地址」）。

如果仍然报 **HTTP 405 Method Not Allowed**，说明“接口地址与协议不匹配”，不是 Key 的问题。
20261110l 起先排掉一条代码级原因：**地址被网关重定向后，旧版会自动把 POST 改成 GET**，
而 `/chat/completions` 只接受 POST，于是返回 405（独立用 POST 验证网关时看不到）。
本版已改为“重定向后保留 POST 重发”，并在失败时给出可照做的排查文案：

- 实际请求的方法/地址（`POST …/chat/completions`）；
- 是否发生过重定向，以及重定向后的最终地址；
- 让您检查 `base_url` 是否为 OpenAI 兼容根地址；
- 三个**本机实测通过**的示例地址与模型；
- 若检测到系统代理，提示“把该域名加入 NO_PROXY 或暂时关闭代理后重试”。

本机实测通过的组合（2026-11-09，咕嘎自身 `SelfAgent._request` 真发请求）：

| base_url | model | 支持视觉 | 本机实测 |
| --- | --- | --- | --- |
| `https://maas.qianwenaiapi.com/compatible-mode/v1` | `qwen3-vl-plus` | 是 | 200（对话/工具调用/截图理解） |
| 同上 | `qwen3.8-max-0902` | 是 | 200（文本+视觉） |
| 同上 | `qwen3.8-flash` | 是 | 200（文本+视觉） |
| 同上 | `qwen-vl-ocr` | 是（OCR 专用） | 200 |

其他常见兼容地址（`https://dashscope.aliyuncs.com/compatible-mode/v1`、
`https://open.bigmodel.cn/api/paas/v4`）**本机没有对应 Key，未实测**，填之前请先点“测试连接”。

非 OpenAI 兼容协议的服务商不能直填（如只提供自家 RPC/SDK 的接口），需要中转成
OpenAI 兼容网关后再填；直填会得到 4xx，而不是“模型能力不够”。

> 配置里有 Key，**不要外传、不要提交仓库**（`ai_config.json` 已在 `.gitignore` 中排除）。

### 配好之后想改 Key / 换模型

右键桌宠 →「⚙️ 模型设置（换模型/端点/Key，测连接）」→ **测试连接（真实请求）** → **保存并生效**，立即生效，无需重启。
同一页还有 **「验证 Key（直连/系统代理）」**：不保存也能先各发一次真实请求，
只显示每条链路的模式、状态码、耗时和**已打码的响应片段**，适合判断“到底是不是 Key 被换了”。

设置页顶部有一行「当前生效」，如实显示：服务商 · 端点 · 模型 · **Key 来源**（本机填写 / 从旧配置继承 / 云端下发）· 打码 Key（只露后四位）。
没配 Key 时这一行是红色「未配置模型」，桌宠右上角也有一个常驻红色「未配置模型」按钮；
点它给出“去配置模型 / 先用本地功能”两个可执行选项。

**关于“咕嘎用的是谁的 API”**：只用你自己在本机填的 Key 和你选的服务商端点。
发行包里没有任何内置、试用或赠送的 Key 与端点；没选服务商（`base_url` 为空）时
不会向任何默认地址发请求，而是明确报「未选择服务商」。缺少配置时对话、拆任务、
写回执、云端派单都直接提示不可用，不会静默失败、不会改用别人的凭据、不会假装成功。
云端派单若账号没有购买云端服务，会收到 `CLOUD_NOT_ENTITLED` / `CLOUD_QUOTA_EXCEEDED`
并翻译成「需购买云端服务」，不会拿运营 Key 兜底。
`ADMIN_ONLY` 提示“仅管理员可用 / 换管理员账号或让管理员开通”；
`BASEURL_REQUIRES_NEW_KEY` 提示“服务商地址变了，旧 Key 不被接受，去模型设置重填”。
这四类 403 都按业务拒绝处理：不重试、不当作网络波动。
云端辅助接口 `/api/agent/vision`、`/api/agent/consult` 同样会返回 403 或 `degraded:true`：
本地任务遇到时**跳过这一步继续做完**，在结果里记一条「云端辅助不可用」，
不整单失败、也不静默假装成功。

> 买软件 = 本机自己填 Key，用本地功能；买云端账号 = 才使用云端服务。两者分开。

### 401/403 怎么自己诊断（20261110q）

模型报 **HTTP 401 / 403** 时，本版把“Key 无效、没有模型权限、额度/余额不足”分开说明，
不再一律写成“Key 问题”，也不会把完整 Key 或 Authorization 头写进日志/文案。

1. **Key 形状先自动洗净**：读取和保存两条路径都会去掉 BOM、零宽字符和首尾空白；
   若 Key **中间**还夹着空格/换行，会直接提示“中间含有空白或换行（清理后长度 N）”，
   并且**不发出请求**。旧版 `ai_config.json` 迁移时同样先洗净再落盘。
2. **错误文案带凭据指纹**：结尾会写
   `本次凭据：长度 N · 前四 XXXX … 后四 XXXX · 来源 main/fallback/legacy`。
   把这四项和昨晚能通的那份配置对比：四项完全一样仍 401，就说明不是换了 Key，
   而是服务商侧的权限/额度/风控变化。
3. **三类下一步**：
   - `invalid/unauthorized` → “Key 本身被拒绝（不是地址问题）”，去模型设置核对后点「验证 Key」；
   - `permission/model_not_found` → “Key 已通过但没开通该模型”，核对模型 id 或换有权限的模型；
   - `quota/balance/insufficient` → “额度或余额不足”，去服务商控制台充值/确认免费额度；
   - 响应体无法归类时，会显示**已打码、截断 240 字**的服务端原文，便于直接发给开发者。
4. **按钮位置**：右键桌宠 →「⚙️ 模型设置」→「验证 Key（直连/系统代理）」。
   直连与系统代理各自独立发一次 POST；两条链路结果不同时，会提示代理很可能就是失败来源，
   建议把该域名加入 `NO_PROXY` 或暂时关闭代理。页面只显示模式、状态码、耗时、打码片段。

### 启动自检与派单输入（20261110r）

**自检通过 ≠ 派单可用**：过去启动自检会给系统输入接口设一份全局类型签名（`SendInput`），
测完不还原；之后豆包/WorkBuddy 派单真正按键时，会报
`ArgumentError: argument 2: TypeError: expected LP_INPUT instance instead of pointer to _INPUT`，
界面表现为「第 1/2 步（豆包）失败：… 缺什么：adapter_exception」，第一步（提交指令）就中断。

20261110r 起：自检改用独立的输入接口实例，不再改全局签名；派单侧每次按键前显式绑定
自己的签名（幂等）。判断是否已修复：右键「导出诊断」，包版本应为 `20261110r`
（自检版本 `r-1`）。q 及更早的包遇到这条 `ArgumentError` 时**重启不解决**，需要换 r 包。

### 豆包 UIA 坐标与 OCR 失败分层（20261110s）

r 及更早的包，豆包窗口 OCR 不可用、走 UIA 降级定位输入框时会报
`KeyError: 2`（界面显示「第 1/2 步（豆包）失败：KeyError: 2。缺什么：adapter_exception」）。
原因是 UIA 返回的输入框坐标是字典 `{"left":…,"top":…,"right":…,"bottom":…}`，
旧代码按列表下标取值。`20261110s` 起同时兼容字典 / 列表 / 元组，字段缺失或尺寸为 0
按原逻辑跳过，不再抛 KeyError；判断版本：包版本 `20261110s`、自检版本 `s-1`。

同版本起，OCR 引擎可用但识别结果为 0 行 0 字时，失败码单独报 `ocr_empty`（阶段
「等待产物」），与 `adapter_exception` 分开。看到 `ocr_empty` 时：在豆包窗口按 Ctrl+R
刷出对话页并保持可见后重派；仍为空到「设置 → 自检」重跑“系统 OCR”并右键「导出诊断」。

### 云端账号入口（常驻，可选）

右键桌宠 →「☁ 云端账号（可选）…」，填服务地址、账号、密码，可先点「测试登录」。
这个入口**始终在菜单里**，不依赖云端是否已启用；空着不填也**不影响本地对话、打开软件、
截图分析**，只影响“派个任务 / 跨设备 / 云端台账”。保存后 `ButlerCloud` 会重新登录，
派单/台账菜单项按新状态出现。云端账号与模型 401 **无关**：模型请求打在本机配置的
`base_url` 上，凭据就是本机 Key。

### 配置与运行数据存放位置（真实落点）

包内**不带** `ai_config.json`，运行数据一律写在用户目录，不写安装目录：

| 内容 | 位置 |
| --- | --- |
| 对话配置（含 Key） | `%LOCALAPPDATA%\GUGA\ai_config.json` |
| 运行数据（安装建议、MCP 工作区、豆包证据） | `%LOCALAPPDATA%\GUGA\runtime\` |
| 交付物 | `%LOCALAPPDATA%\GUGA\deliverables\` |
| 软件自报的安装路径（MCP） | `%LOCALAPPDATA%\GUGA\app_reports.json` |
| 启动日志 | `%LOCALAPPDATA%\GUGA\logs\startup.log`（设 `GUGA_HOME` 时在 `%GUGA_HOME%\logs`；超过 512KB 轮转为 `.1`） |

落点解析顺序：`%GUGA_HOME%` → `%LOCALAPPDATA%\GUGA` → `%APPDATA%\GUGA` → `%USERPROFILE%\GUGA` → 安装目录（仅前几处都不可写时才用，自检会明确提示）。
安装目录里的旧配置只做检测，不会被自动复制；迁移选择记录在 `%LOCALAPPDATA%\GUGA\runtime\legacy_config_prompt.json`。

## 五、启动自检：它到底查了什么

每次启动先弹自检窗，共 **27 项**。每项都**真调用一次**被检能力，拿到真实返回值或真实异常才算测过；做不到实测的标「未测」，绝不因为文件/注册表存在就显示「通过」。结果四态：**实测通过 / 未测 / 降级 / 失败**；降级与失败都写清「缺什么 + 去哪补 + 补完要不要重启」，且行内有「重试」可单项重测。

| # | 检查项 | 怎么实测的（真实调用） | 实测返回什么 | 失败时级别 |
| --- | --- | --- | --- | --- |
| 1 | 旧进程扫描 | `psutil.process_iter` 真实枚举 | 残留进程 PID/名称/说明 | 降级 |
| 2 | Windows 版本 | `sys.getwindowsversion()` + 架构 | 版本/build/架构 | **致命** |
| 3 | 运行库 | `ctypes.WinDLL` 真加载 VCRUNTIME140 / VCRUNTIME140_1 / MSVCP140 / ucrtbase | 成功加载的 DLL 名单；失败给 OSError | **致命** |

## 七、怎么派单（点名外部工具）

### 7.1 一句话原则

在对话窗里**点工具名 + 说清动作和目标**，例如「用豆包写一篇 200 字作文」「用 WorkBuddy 问一句：用一句话介绍你能做什么」「用 JoyCode 把当前工程的编译错误修一下」。
点名后不会由咕嘎的模型代写，而是真的去操作对应软件并核对回执；缺工具时会明确说缺什么、去哪装。

### 7.2 JoyCode（代码任务）

1. 先打开 JoyCode 和目标工程，**再打开右侧 AI 面板**（冷启动时面板默认关闭）。
2. 对咕嘎说「用 JoyCode …」。若识别不到当前工程，会弹「请选择 JoyCode 当前工程」，选中后任务写到该工程的 `.guga\inbox`。
3. **同一目标已有未完成的任务时会被拦截**，提示「同一目标已经在执行，这次不重复派单」；等上一单完成或换一个目标再派。
4. 完成标准是回执 `status=done`；只有文字回答、没有回执不算完成。

### 7.3 WorkBuddy / 豆包（通用任务）

- 豆包不需要提前打开，咕嘎会自动拉起；WorkBuddy 需要已安装并登录。
- 执行期间会把目标软件置前并模拟键鼠，桌宠旁出现控制标识条；点「中止」或按 `Ctrl+Alt+Q`（备用 `Ctrl+Shift+Q`）立即停手。
- 执行中**不要抢焦点**：派单后 3 秒内别点别的窗口。

### 7.4 拿到产物之后

- 完成会弹出产物，并标注来源（如「来源：豆包（界面自动化，非接口调用）」）。
- **先关掉产物弹框，再派下一单**；弹框挡在前面会导致下一次定位失败。

### 7.5 打开软件（简单指令，不需要 Key）

直接说「打开豆包」「打开 WorkBuddy」「打开 JoyCode」或已登记的其他软件名：

- 走**本地意图匹配**（关键词 + 软件名归一化），不调用模型，所以**没有配置 Key 也能用**；
- 路径解析复用 `app_registry.launch_exe()`：优先用软件 MCP 自报路径（`app_reports.json`），
  其次是你手动指定的路径，最后才是声明清单与常见目录/注册表探测；
- **已经在运行就只把窗口切到前台，不会起第二个实例**；系统拒绝切换前台时会如实提示
  “已运行，请从任务栏点开”，不会假装已经打开；
- 没安装或路径失效时给出可照做的提示：装在哪、到「接入面板 → 新增软件」怎么补路径，
  不会静默失败。

**和派单的区别**：只说“打开”就只打开；一旦带上任务（“打开豆包然后写文案”“用豆包生成提示词”）
就走派单/界面自动化链路。实测「用 WorkBuddy 生成照片」这类真任务不再停在第 4 轮，
默认给 80 步预算，可用 `agent_step_limit`（4–200）/ `agent_operation_limit`（6–500）调整。
简单指令（“看看当前窗口”“切到微信”）默认 12 轮、90 秒预算；到上限只会暂停并保存检查点，
回复“继续”即可接着跑，不会把任务记成失败；预算可用 `routine_budget_seconds` 调整。

### 8.5 软件路径不用猜：MCP 只负责发现，指挥仍走视觉

咕嘎找外部软件（WorkBuddy / 豆包 / JoyCode）的 exe，靠声明清单的常见目录、注册表与开始菜单、PATH 与运行进程扫描——这些**不可能穷举别人机器上的安装位置**。本版加了一条更可靠的路：让软件连上来时**自己报一次安装路径**。

先把两件事分开：

| 事情 | 走哪条通道 | 本版状态 |
| --- | --- | --- |
| 发现（这台机器装在哪） | MCP 自报（`report_app`），失败再回退原有探测 | 本版已用脚本验证 |
| 指挥（点哪里、发什么、读什么） | 界面自动化（UIA + 视觉 + 键鼠），**不改用 MCP 派单** | 三家均按原方式 |

**接入状态面板（g 版口径）**

入口有三处：启动自检窗底部「连接器 / 接入状态」、桌宠右键
「🔌 连接器 / 接入状态（MCP）」、桌宠右上角「接入」按钮。面板每款软件一行：

| 状态 | 含义 |
| --- | --- |
| 未安装 | 本机没找到该软件 |
| 未验证：需在官方界面添加 | 装了，但官方界面还没添加 / 本机没检测到配置 |
| 已检测到配置，未验证连接 | 配置或连接痕迹在，但还没握手；**不等于已接入** |
| 通道已就绪，等待软件首次握手 | 咕嘎 HTTP 端点真实握手通过（工具齐全），但还没收到该客户端（`clientInfo`）的 `initialize`；收到第一次真实握手后自动变“已连接”，不用重启咕嘎 |
| 曾连接过，当前未验证 | 曾真实握手成功，但咕嘎 HTTP 服务重启了或那次连接进程已退出；等软件重新连上 |
| 已连接（真实握手 / 5 个工具） | 真实握手通过，且能区分是哪个客户端 |

统一三态口径：**已检测到配置 / 界面已显示 guga（或官方提示添加成功）/ 未验证**。
只有真实握手通过才显示“已连接”；其余任何情况都不写“已接入”。

**豆包是 HTTP 连接器，判定不看 stdio 配置文件**：豆包在「自定义连接器」里填
`http://127.0.0.1:<端口>/mcp`，没有本地 JSON 配置文件。l 版的服务端会在收到
`initialize` 时记录客户端自报的 `clientInfo.name`（如 `豆包`/`doubao`）与进程号，
并写到接入面板读取的同一目录；咕嘎自己的“验证连接”用 `guga-selfcheck` 自报身份，
**不会被当成豆包**——所以不会再出现“握手成功却显示未接入”或“自检完就假装已接入”。

- **可刷新**：面板每次打开都在后台重新扫描，不需要重启咕嘎；扫描中按钮变「检测中…」并禁用，不冻结界面。
- **验证连接**：按该软件的配置真实拉起 `GUGA-Desktop.exe --guga-mcp`，
  `list_tools` 应返回 5 个工具（`report_app` / `get_task` / `report_progress` / `submit_artifact` / `ask_guga`）；
  同时显示最近一次 `report_app` 自报的路径与时间。失败直接写原因：
  配置路径不对 / exe 不存在 / 超时（最长 25 秒）/ 工具清单不符。
- **新增软件**：填软件名称 + 可执行文件路径（带「浏览…」选文件），
  咕嘎生成对应 MCP 配置并可一键复制（复制后读回校验），
  同时把该软件的自报路径写进 `app_reports.json`，下次直接从这里启动。
- 文件夹改名/移动后，若配置里的 exe 已不存在，面板会显示
  「配置里的咕嘎程序已经不存在」，并引导重新复制配置，而不是让你反复重启目标软件。

**怎么让软件报路径（一次配置，长期有效）**

1. **启动就会提醒**：自检通过后，如果发现某款软件「已安装但没接入」，会主动弹
   「咕嘎 · 软件接入提醒」，直接点「现在接入（推荐）」。不想现在弄就点「稍后」，
   同一天同一批软件只提醒一次；之后可从右键菜单「🔌 目标软件接入」进入。
2. **一键复制**：接入窗口里每款已安装软件都有「复制配置」按钮。
   点完会写进剪贴板并**读回比对**，成功时按钮变「已复制」，旁边写明“粘贴到：哪里”。
   如果剪贴板被别的程序占用，会弹出已全选的文本框，按 `Ctrl+C` 手动复制即可。
3. **WorkBuddy（文件型）**：配置落点就是 `%USERPROFILE%\.workbuddy\mcp.json`
   （2026-11-08 三重核对：官方文档写明、`app.asar` 的 `getMcpConfigPath()` 返回该路径、真机点界面一致）。
   - **界面入口（V5.9.3）**：侧边栏「专家·技能·连接器」→ 连接器页右上角**铅笔图标** →
     「MCP 服务管理」→「＋添加 MCP」。它打开的就是同一个 `mcp.json`，界面保存**立即生效**。
   - **直接改文件**：改完必须**完全退出 WorkBuddy（托盘退出；关窗口无效）**再重启，列表才会刷新。
   - **首次连接**：在「MCP 服务管理 → 我的 MCP」点**「信任」**；不点显示灰色、工具不启用。
     之后改 `command` / `args` / `env` 会让信任记录失效，需要**重新信任**。
   - **不要把 `command` 指向 `%TEMP%` 解压目录**：临时目录被清后失效，路径变化还会让信任作废；
     先把咕嘎解压到固定目录（如 `D:\GUGA`），再生成配置。
   配置里的 `command` 会**按你解压的位置自动生成**，
   指向 `GUGA-Desktop.exe` 本身，参数固定 `--guga-mcp`；不依赖 Python，也不会出现开发机目录。
   形状示例（把 `D:\GUGA` 换成你的解压目录）：

```json
{
  "mcpServers": {
    "guga": {
      "command": "D:\\GUGA\\GUGA-Desktop\\GUGA-Desktop.exe",
      "args": ["--guga-mcp"],
      "env": {"PYTHONIOENCODING": "utf-8", "GUGA_CLIENT_ID": "workbuddy"},
      "disabled": false
    }
  }
}
```

4. **JoyCode（只走官方界面）**：官方文档只公布界面入口
   「MCP市场 → 全局配置文件 → +MCP配置」，**没有公布文件系统路径**。
   g 版**不再默认往 `{workspace}/.joycode/mcp.json` 直接写文件**（那是猜测，不是官方依据），
   改为生成可粘贴 JSON（本地程序字段 `type` 必填 `"stdio"`，官方支持 stdio / SSE / streamableHttp），
   并引导你走官方界面。保存后以右下角提示「添加成功，正在更新」为准；官方未要求重启。
5. **豆包（官方自定义连接器，HTTP 优先）**：入口是
   「插件·技能·伙伴 → 插件 → 右上角 + 添加 → 新建自定义连接器」，
   **不是“连接器市场”**。官方传输类型只有 HTTP / STDIO（无 SSE）。
   g 版主程序启动时会自动开本机端点：只绑 `127.0.0.1`、路径 `/mcp`、端口从 18760 起
   （被占用就 +1，实际端口写进 `%LOCALAPPDATA%\GUGA\runtime\mcp_http.json` 与接入面板）。
   **首选 HTTP**：服务器名称 `guga`、传输类型 `HTTP`、
   服务器 URL `http://127.0.0.1:<实际端口>/mcp`、Headers 留空；
   端点不可用时用同一份卡片文本里的 **STDIO 备选**（命令 / 参数 / 环境变量）。
   该连接器**只在豆包「工作」模式生效**，对话模式和 `/`、`@` 都搜不到；
   豆包弹窗原文「自定义连接器仅支持在本地电脑中使用」。
   单独排查：`GUGA-Desktop.exe --guga-mcp-http`；关闭：`"mcp_http_enabled": false`
   或环境变量 `GUGA_MCP_HTTP=0`（WorkBuddy / JoyCode 仍用 stdio，不受影响）。
   官方未要求重启；没有独立的“连通状态/工具清单”页面，只能看「插件 → 管理」。
   门槛：需登录，且需个人订阅或团队/企业额度才能进入豆包工作。
   豆包状态按三态显示：**已检测到配置 / 界面已显示 guga / 未验证**。
   没装豆包就不显示这块；装了但没接入才提示。详见包内 `豆包连接器配置教程.txt`。
6. 连上后让软件调用一次注册工具（工具清单里显示为 `report_app` / 「自报安装位置」），
   传入软件标识（`workbuddy` / `doubao` / `joycode`）、显示名、**exe 绝对路径**、版本、能力。
   咕嘎把它写进 `%LOCALAPPDATA%\GUGA\app_reports.json`（原子写 + 回读校验），
   **以后启动直接按这条路径拉起，不用再猜**；升级或换目录后再调一次即可覆盖旧记录。
   工具清单里另外 4 个（`get_task` / `report_progress` / `submit_artifact` / `ask_guga`）
   是旧工作流的兼容通道，新接入**只需要** `report_app`，不必使用它们。

> **关于 Key**：复制出来的配置里**没有、也不会有**你的模型 API Key——只有本地命令、
> 参数和编码/软件标识这类环境变量。模型 Key 只由你在咕嘎首次配置里自己填，不随包分发，也不内置。
> 豆包连接器的「自定义 Headers」留空，不要填任何 Key。

**路径优先级（从上到下，命中即停）**

1. 用户手动指定（`GUGA_<软件>_*` 环境变量 / 弹窗里选过的路径）
2. MCP 自报路径（`mcp_report`）
3. 声明清单的常见目录、注册表、开始菜单、PATH、运行中进程、绿色版扫描

自报路径会做存在性 + 可执行校验（绝对路径、`.exe`、文件存在且非空）。
**一条脏记录不会让软件再也起不来**：失效时只记一条原因（界面提示「已忽略 N 条失效自报路径」），
继续按第 3 类来源探测。

> MCP 只用于「发现」。派单仍然是把目标窗口置前、模拟键鼠、核对回执；连了 MCP 也不会把任务改从 MCP 通道发。

## 九、已知限制与风险（如实说明）

1. **未签名**：首次必过 SmartScreen；部分安全软件会拦截键鼠模拟。
2. **外部软件缺席**：不静默失败，界面明确说明缺什么、去哪装。
3. **界面指挥依赖前台窗口**：执行时会把目标软件置前并模拟键鼠；控制时桌宠旁出现标识条，`Ctrl+Alt+Q`（备用 `Ctrl+Shift+Q`）或条上「中止」立即停手；两个热键都失败时条上会明示。
4. **JoyCode 默认只认常见位置**：默认 `D:\JoyCode\JoyCode.exe`（或 `D:\JoyCode\bin\joycode.cmd`）与 `GUGA_JOYCODE_LAUNCHER`；装在其他盘时，让 JoyCode 调一次 `report_app` 自报路径，或手动设置该环境变量。
5. **WorkBuddy 有额度限制**：免费额度用尽会返回额度提示，不伪造答案。
6. **外部生成很慢**：本份 8 页 PPT 19:05 建会话 → 19:53 落盘（约 48 分钟，前 40 分钟无产物），不适合现场跑全流程。
7. **系统 OCR 依赖语言包**：只有英文包时中文会读错；g 版自检第 12 项真执行 `-File windows_ocr.ps1` + 真识别中文，按字符重合率 ≥90% 判定，并给出语言包安装路径。OCR 不可用只判降级，豆包派单降级走 UIA + 剪贴板，不中断任务。
8. **vosk 离线模型不随包**：本安装包**不含**中文语音模型，自检第 9 项会如实标「未测」，不会显示通过。首次使用需联网下载约 40MB：运行 `GUGA-Desktop.exe --download-vosk-model`（默认先走国内镜像 hf-mirror.com，实测约 8 秒下完并校验 SHA256；镜像失败自动回退官方源），或手动下载 `https://alphacephei.com/vosk/models/vosk-model-small-cn-0.3.zip` 解压到 `%GUGA_HOME%\models\vosk-model-cn`（默认 `%LOCALAPPDATA%\GUGA\models\vosk-model-cn`）。下载完成后再点自检「重试」。**不承诺离线语音开箱可用**；未下载只影响「按住说话」的离线识别。
9. **声纹识别默认关闭**：模型未随包（`resources/models/speaker` 只有说明文件）。
10. **云端依赖**：派单/台账/跨设备依赖你购买云端账号时拿到的服务地址（在 `ai_config.json` 的 `cloud` 段填写，发行包不预置地址）；未填或不可达时本地能力不受影响。
11. **缩放与分辨率**：交付前四批验收在 **1920×1080 + 真实 125% 系统缩放** 下全通过；1366×768@125% 为真实切换分辨率；125%/150% 各有一批为 `QT_SCALE_FACTOR` 布局代理（系统 DPI 仍 125%），**不是真改系统 DPI**；**2560×1440 本机适配器不支持，结论为不适用**。
12. **复合链路未跑通**：「豆包提示词 → WorkBuddy 出 PPT → JoyCode 落地」没有完整成功回执；19:27 尝试因模型 HTTP 403 中止。**不要对外说已打通**。
13. **JoyCode 工作区**：会从 JoyCode 配置读当前工程；读不到或配置不明确时仍需在弹窗里手动选一次，选中后任务写到该工程 `.guga\inbox`。
14. **Trae 未适配**：界面指挥 0 工具调用空转；元宝/智谱清言/Kimi 未测。
15. **模型能力有限**：`glm-4.6/4.5v/4.5` 实测因账户额度返回 429；当前配置的 `qwen3.8-max-0902` 探测中「强制工具调用」不通过（`tool_choice` 被忽略），长多步 GUI 任务稳定性有限。
16. **未做物理新机验证**：干净环境验收 = 全新用户目录 + 最小 PATH（仅 System32）+ 只读安装目录 + 多分辨率/缩放切换；不是另一台物理机。

## 十一、出问题时看哪里

**先把诊断包发给我们**：右键菜单 →「🩺 导出诊断（发给我们）」，或模型设置页的
「一键导出诊断」。会在桌面生成 `咕嘎诊断_年月日_时分秒.zip`，内含版本号/构建 SHA、
自检逐项真实结果、最近 30 分钟日志 + 最近一次任务时段（含失败时段）的日志、
最近一次任务的 `result.json`、任务台账摘要、失败码与证据目录清单；
API Key / Authorization / Bearer / sk-* 等已脱敏，`ai_config.json` 原文不会被打包。
版本/构建 SHA/包内容摘要优先读包内固定位置 `_internal/build-info.json`；能找到原始 zip 时
同时实测其 SHA256 并对照同名 `.sha256` sidecar，找不到就如实标注来源。

**不依赖真实模型 Key 的复验入口（i 版新增）**：`--simulate-adapter-failure ocr_degraded`
会走真实 `adapter_chain` 跑两步降级续跑；`--simulate-adapter-failure adapter_exception`
会输出失败码四段。两者都用桩适配器，不联网、不读任何 Key，结果写 `--simulate-out` 指定的 JSON。

| 现象 | 先看 | 处理 |
| --- | --- | --- |
| 双击没反应 / 秒退 | 自检是否报「运行库/内置依赖」致命 | 重新完整解压，加杀软白名单 |
| 卡在自检很久 | OCR / UIA / 外部软件 / MCP 探测（并行） | 正常；超过 20 秒单项会标未测/降级 |
| 报「缺少界面必需模块」 | 包被部分删除 | 重解压，不要单拷 exe |
| 对话报 401 | 模型设置「测试连接」 | Key 是否完整、base_url 是否为 OpenAI 兼容地址 |
| 对话报 429 / 提示余额不足 | 服务商后台额度 | 充值或换有额度模型；不是程序故障 |
| 提示「请先配置模型」 | `%LOCALAPPDATA%\GUGA\ai_config.json` | 按第四节填 Key，或走向导 |
| 派单提示装软件 | 建议安装 / 自检第 26 项（外部软件） | 按提示安装并登录 |
| 跨设备提示「没有可用设备」 | 设备选择框是否为空 | 确认另一台已上线并配对；离线设备不会被列出 |
| 跨设备提示「缺少工具」 | 选中设备的工具清单 | 换有该工具的设备，或在目标机安装 |
| 跨设备提示「清单拉取失败」 | 网络 / 服务端可达性 | 重试一次；仍失败就本机跑，别静默降级 |
| 语音没反应 | 自检第 10 项（麦克风真实开流） | 开隐私授权、插好设备 |
| 双击 .pptx 打不开 | 本机是否装了 Office/WPS | 用 `docs\demo\放映-WorkBuddy-8页.html` |
| 正在控制时想停手 | 桌宠旁标识条 | 点「中止」，或 `Ctrl+Alt+Q` / `Ctrl+Shift+Q` |
