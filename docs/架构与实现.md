## 一、整体数据流

```
用户语音/文字："把本周实验数据整理成周报"
        │
        ▼
┌──────────────────┐   ①POST /api/tasks    ┌────────────────────────┐
│  桌宠端           │ ────────────────────► │  云端大脑               │
│  PyQt5 常驻       │                       │  Express + 文件型台账   │
│  形象 / TTS / 交互│ ◄──────────────────── │  拆解 → 派单 → 验收     │
└──────────────────┘   ②台账状态回推        └───────────┬────────────┘
                                                        │ ③派单（配对令牌，不暴露内网）
                                                        ▼
                                            ┌────────────────────────┐
                                            │  真机执行本体            │
                                            │  领单 → 操作软件 → 取证  │
                                            └───────────┬────────────┘
                                                        │ ④真实鼠标键盘 + 截图
                                                        ▼
                                            豆包 / Kimi / 元宝 / 智谱
                                                        │
                                            ┌───────────▼────────────┐
                                            │ ⑤答案回传 + 证据墙       │
                                            │ ⑥LLM 按验收标准裁决       │
                                            │   不合格 → 打回重做      │
                                            └────────────────────────┘
```

**为什么是"配对"而不是"填 IP"**：执行本体装在用户自己电脑上，通常没有公网地址。它在云端生成 6 位配对码后主动连出并维持心跳，云端由此知道"这台机器在线、能力如何"。评委不需要配路由器、不需要公网 IP。

## 二、任务台账状态机

一条子任务（`st`）在云端只有这几种状态，流转由代码强制，不允许 LLM 自由发挥：

| 状态 | 含义 | 进入条件 | 出口 |
|---|---|---|---|
| `pending` | 已拆解未派发 | 拆解完成 | 派单 → `running` |
| `running` | 执行方已领单 | 设备心跳 + 领单成功 | 交付 → `review`；设备掉线 → `paused` |
| `paused` | 挂起 | 用户暂停 / 设备离线 | 恢复 → `running` |
| `review` | 待验收 | 执行方回传产物 | 裁决 → `done` 或打回 |
| `done` | 通过 | 裁决 pass | 复盘钩子 |
| `failed` | 异常 | 连续 3 次仍不达标 | 如实上报，不假装成功 |

**关键约束**：`MAX_ATTEMPTS = 3`。三次交付仍不达标时，系统标记异常并如实告诉用户"没做成"，而不是把不合格的东西包装成合格。这是"监工"可信度的底线。

## 四、真机执行的三个硬问题与解法

### 1. 坐标为什么会偏：DPI 感知必须在所有第三方导入之前

`pyautogui` 与 `PIL` 在 import 时会缓存屏幕 DC。若此时进程还是 DPI-unaware，后续再声明感知也改不回来——表现是"只截到窗口左上角"且点击整体偏移，而且**不报错**。

所以 `agent/guga_executor.py` 的第一行逻辑就是 `_enable_dpi_awareness()`，早于任何第三方 import；并且返回的是**系统读回的真实级别**，不是"我调了就算成功"（exe 清单若已声明过 DPI，设置会抛 `E_ACCESSDENIED`，此时谎报 per-monitor 会让后续排障全错）。

### 2. 视觉为什么认不出按钮：不是模型不行，是送进去的字太小

窗口在 1920 屏上满宽送 800px 图，正文只剩 5.8px；4K 屏只剩 2.9px。解决办法不是换更贵的模型，是**按屏幕宽度自适应放大送图（800→1600）**，再加两级区域放大定位兜底：

```
locate(全窗截图) 失败
   → 只截底部输入带放大再看
   → 只截左侧栏放大再看
```

面积更小、像素更清，成本反而更低。

### 3. 窗口为什么抓错：几何只有一个来源

窗口贴边被裁、窗口比标称窄时，写死 800 或按标称宽换算都会整体偏移。所以：

- 窗口几何只走 `win_rect()`：`GetWindowRect` 单次快照 → 校验（正宽高 / 不小于 200 / 与屏幕有交集）→ 不合法按标题重找 → 再不行退屏幕区域。**绝不"夹一下就当能用"**，夹完位置全错比崩掉更坏。
- 截图只走 `grab()`：求交屏幕 + 正宽高 + 失败回退全屏 + 永不抛异常（除 FAILSAFE）。

## 五、安全机制

| 机制 | 实现 |
|---|---|
| 紧急停手 | `pyautogui.FAILSAFE = True`，鼠标甩到屏幕左上角立刻中止 |
| 剪贴板还原 | 执行前保存原内容，结束后恢复，不偷用户剪贴板 |
| 会话隔离 | 只操作"新对话"，绝不污染用户已有会话与画布任务 |
| 隐私下线 | 微信 / 企业微信 / QQ 因涉及私聊内容，主动移出支持列表 |
| 证据可复核 | 每步截图随任务上传证据墙，可按任务、按步骤逐帧回看 |
| 凭据隔离 | API Key 只放服务端 `.env`，前端与仓库内均无明文 |

## 六、桌宠端要点

- **渲染**：`ui/sprite_animator.py` 走序列帧 + manifest 驱动，支持 LRU 帧缓存（默认上限 256 帧），长动作只取循环段，避免内存爆掉
- **TTS 跨线程**：`QMediaPlayer` 只允许主线程操作，后台线程只合成 mp3，通过 `pyqtSignal` 回主线程播放
- **本地知识库**：`core/knowledge_rag.py` + `knowledge/`，检索结果作为 system 上下文注入，命中标签可切换（战棋参考 / 生产力 SOP）
- **管家能力包**：`armor_packs/*.json` 定义能力边界与话术，`core/mode_manager.py` 负责切换与状态持久化

## 七、游戏军师链路（战棋帮助）

咕嘎的"看对局"有三级降级，保证在尽可能低成本的通道拿到棋盘：

```
power.log 日志解析（零 API，log_reader.py）
   → 不可用时 GLM-4.6V 截屏分析（core/vision.py）
   → 胜率评估走蒙特卡洛模拟（battle_sim.py，n=600 后台线程）
```

- `log_reader.py` 带 `_prune_ents()` 内存清理：非 PLAY 区实体自动淘汰，总量限 3000，长对局不涨内存
- `match_history.py` 保留最近 5 场战绩，`comp_analysis.py` / `lineup_planner.py` 据此给对手流派与己方方向建议
- 棋盘/卡牌解析依赖 `lib/` 内第三方只读库（HearthMirror 等），许可见 `THIRD_PARTY_NOTICES.md`

## 八、语音链路（两个身份共用）

```
按键说话（voice_dialog.py）──┐
持续语音对话（realtime_voice.py）─┤→ 对话引擎 → TTS 朗读
管家事务播报（agent_voice.py）─┘     （tts_engine.py：edge-tts 主 / 豆包兜底）
```

- `tts_engine.py` 的跨线程约束：QMediaPlayer 只在主线程操作，后台线程只合成 mp3，用 `pyqtSignal` 投递回主线程播放
- 临时 mp3 用完即删，启动时清理残留，队列限长 4，防止长会话堆积
- 持续语音对话支持流式播放、静音、耳机语音打断与断线续接；默认不做声纹匹配，无需录入主人声音
