## 0. 先检讨：上一轮我为什么漏了这些

1. **把“验收通过”当成了“用户体验通过”。** 上一轮核心批次 17/17 全绿，但验收矩阵只验证“能不能走完”，没验证“评委看不看得懂、知不知道下一步”。点“退出”实际没退、关窗口静默消失这类问题，全部能通过自动化断言。
2. **只测了正向路径，没测“拒绝/关闭/离线/中断”。** 空 Key、错 Key、不填就继续、点 X、点“稍后”、断网、目标软件没登录——这些才是首启真正的高频分支，我只跑了“填对 Key → 成功”。
3. **用“代码里有这句文案”代替“界面真的出现了这句文案”。** 例如接入教程、安装指引、登录提示，代码里都有，但入口被藏在一次性的启动提醒里，用户根本走不到。
4. **忽略了“一次性提示”的可用性。** 启动提醒同一天只弹一次，点“稍后”之后当天不再弹，也没有常驻入口——等于第一次没看清就永久错过。
5. **没有按“评委真实机器”建模。** 上一轮安装目录仍在 `d:\rengongzhineng\...\clean_bench\.cache`（带项目路径），不是桌面解压；机器上装了 JoyCode/WorkBuddy，不等于评委机器有。本文已把这类“模拟/真实”差异单独标注。
6. **没把“等待”当成缺陷。** 同步扫描、保存时阻塞探针、点按钮后无进行中状态——这些在自动化里只是“慢一点”，在人眼里就是“卡死/没反应”。

本次的检查口径改为：**每一步都问“我看到什么 / 我期望什么 / 实际是什么 / 如果我不是开发者能不能照做”。**

### 阻断（会让评委直接认为“坏了/不能用”）

#### F-01 自检窗口点“退出”并不会退出；“致命”状态下点退出仍会继续进入
- 严重度：阻断
- 复现：双击启动 → 自检窗口 → 点左下“退出”（或点窗口 X）→ 观察是否退出。
- 期望：点“退出”= 结束进程；出现“× 致命”时主按钮禁用，用户只能退出并按提示补齐，不能带病进入。
- 实际：`run_startup_gate()` 在 `gate.exec_() != Accepted` 时直接 `return`，`comp_main.py` 不检查返回值，继续进入配置向导/桌宠。所谓“退出”只是关掉了自检窗口。关闭窗口 X 同理。致命项时按钮文案变成“缺少必需环境，无法继续”，但“退出”依旧放行，后面才崩。
- 涉及文件：`ui/startup_gate.py:224-235`、`ui/startup_gate.py:92-98`、`ui/startup_gate.py:187-194`、`comp_main.py:86-95`
- 证据：[代码只读]（路径确定，未单独实跑）

#### F-02 首次向导点 X 关闭 → 进程静默退出，没有任何提示
- 严重度：阻断
- 复现：首次启动 → 向导出现 → 点右上角 X。

## 3. 专项检查结论

### 3.1 没有模型 Key 却能进入后，需要模型的路径会不会静默用非用户凭据？
- **会（严重，F-05）**：只要 `api_key` 非空、`base_url` 为空，对话会发往 `https://api.deepseek.com` 并默认模型 `deepseek-v4-flash`。
- **不会**把空 Key 当有效 Key：`ask()` 在 `api_key` 为空时直接 `failed("未配置 API Key")`，不会发请求。
- 其余需要模型的入口（截图分析、完整对话）没有统一的“先配置”前置守卫，失败文案各不相同；本次未逐个实跑，列为待补验。
- 语音链路存在环境变量 Key 的静默兜底（F-23）。

### 3.2 界面上有没有地方显示“当前用的哪个模型/哪个端点”？
- 有，但很弱：模型设置里的“当前档位：… · 模型名”和测试结果“模型/端点”；自检的“配置与运行目录”一行。
- 主桌宠界面没有；只有半透明“模型”按钮（F-18）。评委不点开就不知道当前用的是什么。

### 3.3 多款软件同时接入时状态会不会互相干扰？
- 代码层面基本隔离：每个软件独立 `channel_status`、独立 `.guga/mcp-connections/<app>.json` 连接见证、独立 `GUGA_CLIENT_ID`、独立配置路径；一个软件配置损坏不会阻断另一个。
- 三个软件共用同一个“工作区”和同一行“MCP server（mode/command）”；工作区一旦变化，三条会一起失效，但卡片仍逐条显示状态（见 F-08）。
- 本次未实跑“三家同时接入后逐个断开”的交叉场景，列为待补验。

### 3.4 所有“没有反馈的等待”
| 场景 | 等待时长 | 界面表现 | 结论 |
|---|---|---|---|
| 向导保存（有探针在跑） | 最长 25s | 窗口冻结、无进度 | F-03 |
| 向导测试连接 | 最长 25s | 有“测试中…（最长 25 秒）”，无秒数/取消 | F-16 |
| 云端测试登录 | 最长 20s | 只有“测试中…” | F-16 |
| 自检的 4 个慢项 | 每项最长 20s | 无占位行，摘要停在“已查 9 项” | F-17 |
| 接入弹窗首次打开 | 可能 10s+ | 只有“正在检测…” | F-13 |
| 接入卡片“测试连接” | 最长 25s | 无进行中状态、按钮不禁用 | F-14 |
| 聊天请求进行中再输入 | 不定 | 完全无提示 | F-22 |
| 派单后等云端拆解 | 不定 | 有“我拆拆看……”气泡，8 秒后消失 | F-09 |

## 4. 评委最可能卡住的 5 个地方（一页版）

1. **自检点“退出”没退出。** 评委想放弃，点退出却继续弹配置向导；出现“致命”时也照样放行。第一印象直接变成“这软件不受控制”。（F-01）
2. **关掉首次向导，程序静默消失。** 没有二次确认、没有退出说明，看起来就是崩溃。（F-02）
3. **不填 Key 进去后，对话只回一句 `( connection: 未配置 API Key )`，8 秒后连这句都没了。** 看不懂、也不知道去哪补。（F-04 + F-09）
4. **接入教程只有一次，点“稍后”当天再也找不到入口；移动文件夹后接入永久失效，界面还让一直重启目标软件。**（F-07 + F-08）
5. **保存/测试/接入检测全是长阻塞且没有进度。** 评委点了“保存”或“测试连接”，界面十几秒不动，会直接判定卡死并强杀进程。（F-03 + F-13 + F-14）
