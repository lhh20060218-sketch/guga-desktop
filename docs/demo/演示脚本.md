# 咕嘎 · 现场演示脚本（4 分钟）

> 三段标注（与 [能力边界.md](能力边界.md) 一致）：
> **A = 在本包真机实测通过**，可现场直接演；
> **B = 机制支持、但没在本包实测**，现场跑必须同时准备「没跑通怎么说」；
> **C = 明确没做到**，只讲、不演，也不说已支持。
>
> 本脚本里没有排练动作。预生成内容一律当场说明来源与时间；失败一律说失败。

## 主流程（4 分钟）

### 0:00–0:25 开场（不操作）

- **说**：咕嘎不是聊天窗，是桌面上的常驻伙伴。它自己不写内容——它去操作这台电脑上已经装好的 AI 工具，每一步回到咕嘎核对回执。**没有真实回执就不交付。**
- **说**：今天讲三件事：开箱能不能跑、能不能真的替我操作别的软件、哪些还没做到。

### 0:25–1:00 启动与自检（A）

- **点**：`GUGA-Desktop.exe`（首次 SmartScreen：更多信息 → 仍要运行）。
- **屏幕出现**：`咕嘎 · 启动自检`，12 项，约 2–3 秒；按钮三选一：`全部通过，继续 →` / `带着降级项继续 →` / `缺少必需环境，无法继续`。
- **点**：继续 → 建议安装（只列真实没装的）→ 关闭 → 首次配置向导（已配过则跳过）→ 桌宠出现。
- **说**：缺运行库/系统版本直接不让进；缺外部工具只降级。不假装能跑。
- **卡住切**：白屏/20 秒无窗 → 重开一次；仍不行 → 播 `guga-intro-20261107.mp4`（27 秒，**提前做的**）并说明。

### 1:00–1:15 桌宠与菜单（A）

- **点**：左键点形象 → 输入条「少爷请吩咐…(Enter 发送, Esc 关闭)」；右键 → 菜单：对话 / 完整对话·复杂任务 / 模型设置 / 截图分析 / 语音输入 / 战棋 / 趣味动作 / 退出。
- **说**：没配云端账号时菜单里没有「派个任务…」「任务台账」，这是设计。

### 1:15–2:05 豆包：没开会自己打开（A，真机）

- **前提动作**：提前把豆包窗口关掉（任务管理器里杀干净）。
- **点**：输入条输入 `用豆包写一篇 200 字作文` → Enter。
- **屏幕出现**：桌宠旁的**控制标识条**（目标软件 / 当前步骤 / 暂停·中止）；豆包被**自动拉起**（实测约 16 个进程），窗口置前，输入框被填入，回车。
- **屏幕出现**：豆包开始生成；约 31 秒后咕嘎弹出「咕嘎 · 豆包 的产物（真机执行）」，里面是 `来源：豆包（界面自动化，非接口调用）`、`已保存：…\deliverables\guga-豆包-….txt`、以及「未走接口」说明；**正文在保存的产物文件里**。
- **说**：三件事同时发生——它**自己把软件拉起来**（不需要你先开）、**自己打字发送**、**把回答原文抓回来落盘并标注来源**。留档：`result.json` 里 `text` 122 字（`deliverable-122chars.txt` 同为 122 字），从 `open_window` 06:08:39.272 到 `capture_verify` 06:09:10.319，约 31 秒；`local_model_used=false`。
- **说（如实细节）**：这次豆包窗口先出现了空白，它自己检测到并在 4 秒内恢复（`blank_detected` → `blank_recovered`），然后才继续。不是每次都一步到位。
- **说**：这也解释了为什么它敢让你关掉豆包：开没开不影响，没开它会开。
- **卡住切**（按实际分支说，别圆场）：
  - 豆包窗口**一直空白**：空白一般会自愈（留档这单 4 秒恢复）；**恢复不了**才报 `window_blank`「豆包窗口白屏…请在豆包窗口按 Ctrl+R 或重启豆包」——照做一次，仍不行就说「这台机器的豆包自己打不开，我跳过这段」，转 WorkBuddy 段。
  - 豆包**没安装**：会明确说「本机没装豆包…到 www.doubao.com 下载…」——照读，转 WorkBuddy 段。
  - 豆包**停在登录页**（未验证分支）：说明「豆包需要登录」，现场人工登录一次即可继续（不登录就跳过）。
  - 30 秒无任何动作：说「这单没跑起来」，最多重试 1 次，然后跳段。

### 2:05–2:45 WorkBuddy：真机派单并抓回原文（A，真机）

- **说（预防针）**：这段同样会动鼠标键盘，随时 `Ctrl+Alt+Q`（备用 `Ctrl+Shift+Q`）或点标识条「中止」。
- **点**：输入 `用 WorkBuddy 问一句：用一句话介绍你能做什么，不要生成文件` → Enter。
- **屏幕出现**：完整对话窗 + 控制标识条；WorkBuddy 输入框被填入、回车；约 55 秒后回答被带回。
- **说**：这单有留档：`answer_chars=174`、`generate_ms=34253`（生成 34.3 秒）、`elapsed_ms=54860`（全程 54.9 秒）、`source=workbuddy-ui`。这几个字段都在 `docs\demo\evidence\20261108-workbuddy-inpackage\package.json` 里，评委可以自己核对。
- **说**：这句话不是咕嘎写的，是 WorkBuddy 写的、被它抓回来的；抓回来的原文在 `answer.txt`，174 字。
- **别说**：「模型请求增量 0」——回执里**没有这个字段**，无法从文件核实，不要拿它当证据。
- **被追问「怎么证明它没调模型」时**（内部备查，不主动讲）：可出示 `docs\demo\evidence\20261108-recorder-local-endpoint\recorder.log`——本地记录端点 `127.0.0.1:18110` 从 05:36:58 启动后**没有任何请求行**。同时说明：这只证明该端点未被调用，**不等于全链路零调用**；不对外承诺。
- **卡住切**：输入框没被填 / 回读不一致 / 60 秒无变化 → 说「这单没提交成功，它的规则是没生成信号就不算发出」，最多重试 1 次，然后转放映页。**绝不**把 19:53 那份 PPT 说成本次结果。

### 2:45–3:25 预生成成品（产物为真实回执，**明确非现场生成**）

- **点**：快捷方式打开 `docs\demo\放映-WorkBuddy-8页.html`（Edge，`←/→` 翻页，`F` 全屏）。有 Office 的机器可改双击原 pptx。
- **说**：这份是 **2026-11-07 19:05 建会话、19:53:49 落盘** 的 WorkBuddy 真实产物；前 40 分钟没有任何产物增长，所以**现场不跑**，用它讲。
- **说**：它与 WorkBuddy 自己产物目录里的文件字节一致（SHA256 `8e206cd3…`），不是我们另做的。
- **说（版本差异，别混）**：台上的放映页是我的机器用 Edge 打开的重排版面，**不是 PowerPoint 原始渲染**。
- **卡住切**：Edge 也打不开 → 用文件属性（35,782 字节 / 19:53）口述结构，别现场修文件。

### 3:25–4:00 边界与收尾（B/C，说清不演）

- **JoyCode（A 的「设工作区」/ B 的「自动识别」）**：**设置工作区后已跑通一单**（`status=done`，产物 4,894 字节，回执在 `docs\demo\evidence\20261108-joycode-workspace\`），但**自动识别工作区还在修**。现场口径：
  「JoyCode 设好工作区是能跑通的，今天不现场跑；它现在需要先确认 JoyCode 已打开目标工程，如果咕嘎提示找不到工程，要在弹窗里**手动选一次**。这个自动识别还在修，修完我再更新口径。」
- **MCP（B）**：WorkBuddy / JoyCode 写入配置后重启能自动连接（有工具清单与连接日志），但**经 MCP 的任务闭环还没有成功回执**；豆包没有本地配置文件，连接器必须登录后在界面新建，只能人工。
- **跨设备（A 的 UI / C 的真机）**：设备选择框已在本包实测（只列在线、显示已装工具、不自动选，三类失败都有明确提示）；**真实两台机器的服务端派单仍未验证**，所以不现场派。
- **复合链路（C）**：豆包→WorkBuddy→JoyCode 端到端**没跑通**，不演，也不说已支持。
- **收尾**：能证明的给证据，做不到的直接说没做到。

## 现场禁忌

- 不说「任意软件都能自动完成」「跨工具链已经打通」。
- 不在现场跑十几分钟以上的 PPT 生成。
- 不把本地假模型服务回显的截图（`runtime\clean\shots\j9_simple.png`）当真实模型证据。
- 不把 `runtime\deliverables\桌面AI助手能力介绍.pptx`（0 页）当成品打开。
- 不在失败后连点重试；演示的信用靠「失败就说失败」。
