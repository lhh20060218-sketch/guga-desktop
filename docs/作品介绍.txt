咕嘎（GUGA）桌面智能管家 · 作品介绍
================================================================

一、一句话说明
----------------------------------------------------------------

咕嘎是一只住在 Windows 桌面上的企鹅管家：它既能陪聊，也能听懂或看懂屏幕，
并且能在你点名时，真的去操作豆包、WorkBuddy、JoyCode 等外部软件完成任务，
最后把产物和「来源/回执」一起交给你。

----------------------------------------------------------------
二、解决什么问题
----------------------------------------------------------------

1. 普通聊天助手只能“说”，不能真的替你操作另一个软件。
2. 真机操作类工具常常“假装做了”：模型直接生成文字，没有真实调用记录。
3. 普通用户不会配 API、不会装环境，拿到代码包也跑不起来。

咕嘎的取舍：宁可明确说“没装/没调起/没有回执”，也不拿模型代写冒充；
配置和数据全部写到用户目录，安装目录只读也能用。

----------------------------------------------------------------
三、核心能力
----------------------------------------------------------------

1. 桌宠陪伴
   桌面常驻、可拖拽、状态气泡、按住说话/唤醒词（取决于模型与麦克风）。

2. 对话与模型配置
   内置智谱/DeepSeek/通义等平台预设，图形化填 Key、真实测试连接、保存即生效。
   没有配置模型时，界面常驻显示「未配置模型：对话 / 完整对话 / 截图分析不可用」，
   点它给可照做的配置入口，不会几秒消失，也不会假装成功。
   任何需要模型的请求都只打到你选的服务商与端点；没选服务商就明确报
   「未选择服务商」，不存在隐式默认端点。发行包里没有内置、试用或赠送的 Key。
   设置页显示当前服务商、端点、模型与 Key 来源（本机填写 / 从旧配置继承 / 云端下发）。
   只配一个多模态模型即可覆盖对话、任务拆解与截图理解；主模型不支持看图时，
   可在「模型设置 → 视觉模型」单独指定 vision_base_url / vision_api_key / vision_model。
   安装目录里的旧配置不会被自动继承：启动时打码展示并询问，默认「重新填写」，
   只有用户明确点「沿用这份配置」才写入。

3. 点名外部工具（真机派单）

   这里有两件事，分开做：
   - 发现（这台机器装在哪）：优先读软件通过 MCP 自报的路径（report_app，
     落到 %LOCALAPPDATA%\GUGA\app_reports.json）；没有才回退声明清单的常见目录、
     注册表/开始菜单、PATH 探测。自报路径失效只记一条原因并继续回退，不会卡死。
   - 指挥（点哪里、发什么、读什么）：仍然走界面自动化（UIA + 视觉 + 键鼠）。
     MCP 只负责发现，不承担派单。

   接入引导：
   - 启动自检通过后，若发现软件“已安装但没接入”，主动弹「软件接入提醒」，
     直接说清“不配只能猜路径 + 纯视觉”“配了就能记住路径”两件事。
   - 接入窗口每款软件都有「复制配置」：写剪贴板并读回校验，成功变「已复制」，
     旁边写明粘贴位置；失败弹可全选文本框兜底。
   - 豆包没有 JSON 配置文件，界面里单独成一块卡片；
     官方入口是「插件·技能·伙伴 → 插件 → 右上角 + 添加 → 新建自定义连接器」。
     g 版本体提供 streamable HTTP MCP 端点：只绑 127.0.0.1、路径 /mcp、
     端口从 18760 起被占用就 +1（实际端口显示在卡片上，也写进 runtime\mcp_http.json）；
     豆包首选 HTTP（服务器名称 guga、传输类型 HTTP、URL http://127.0.0.1:<实际端口>/mcp、
     Headers 留空），端点不可用时用同卡片里的 STDIO 备选。
     连接器只在豆包「工作」模式生效，对话模式和 /、@ 都搜不到；
     配《豆包连接器配置教程.txt》，另有「复制连接器字段」（字段：值，不是 JSON）；
     豆包状态按三态：已检测到配置 / 界面已显示 guga / 未验证；没装就不显示这块。
   - JoyCode 官方只有界面入口「MCP市场 → 全局配置文件 → +MCP配置」，
     没有公布文件系统路径；本版不再往 {workspace}/.joycode/mcp.json 写文件，
     只生成含 "type": "stdio" 的可粘贴 JSON，并引导走官方界面。
   - 接入状态面板：自检、向导、主界面都能进；每款软件一行，
     三态：已检测到配置 / 界面已显示 guga / 未验证；
     只有「验证连接」真实握手拿到 5 个工具才显示“已连接”，其余不写“已接入”。
   - 「验证连接」做真实握手：按配置拉起 GUGA-Desktop.exe --guga-mcp，
     list_tools 应拿到 5 个工具（含 report_app），并显示最近一次自报路径与时间；
     失败写明配置路径不对 / exe 不存在 / 超时 / 工具清单不符。
   - 「新增软件」：填名称 + 可执行文件路径（可浏览选文件），生成配置可一键复制，
     同时写入 app_reports.json，下次直接从这里启动。
   - 复制出来的配置不含任何模型 API Key，只有本地命令和参数；
     命令指向解压出来的 GUGA-Desktop.exe 自身，不依赖 Python，也不含开发目录。
   - MCP 接入 ≠ 模型可用：MCP 只解决“软件装在哪”，模型 Key 仍须用户本机自填。

   - 豆包：自动拉起窗口，界面自动化输入、提交、读回结果。
   - WorkBuddy：UIA 定位编辑器 + 哨兵校验 + 页面归属校验（page_mismatch），
     防止输入落到错误会话。
   - JoyCode：统一 Adapter 入口，从 JoyCode 配置读取当前工程；
     读不到时弹窗选择工作区；发送按钮兜底；回执 status=done 才算完成。
   缺工具时给安装指引；调不起或没有回执时明确失败，不代写。

4. 任务与交付
   同一目标重复派单拦截、执行台账、产物来源标注、交付闸（无真实回执不可交付）。

5. 启动自检
   27 项真实探测（每项都真调用一次，不用“文件存在”冒充通过）：
   旧进程、系统版本、运行库 LoadLibrary、模块真实 import、真实 DPI、
   配置写入回环、ffmpeg 真执行、语音模型真加载、麦克风真开流、中文字体真渲染、
   OCR 真执行 -File + 真识别中文（重合率 ≥90%）、UIA 真读控件、目标软件 UIA 可读、
   剪贴板 Unicode 回环、整屏截图非黑、PrintWindow 真像素、EnumWindows、
   窗口定位与前台归属、SendInput 真发事件、%TEMP% 可写、长路径、PPT 真生成、
   MCP 真握手 5 工具、模型端点轻探测、外部软件可派单预检、模型准入。
   结果四态：实测通过 / 未测 / 降级 / 失败；降级与失败写清缺什么、去哪补、
   补完是否重启，且可单项「重试」。
   OCR 不可用只判降级：豆包派单降级走 UIA + 剪贴板，不中断复合任务。
   打包时断言“包内自检项数/版本 == 源码”，不一致直接构建失败。
   出现致命项时点「退出」会真的退出，不会带着致命问题进入桌宠；
   首次向导点 X 不再闪退，而是询问：稍后配置 / 最小化到托盘 / 退出。

----------------------------------------------------------------
四、技术路径
----------------------------------------------------------------

- 界面：PyQt5 桌宠窗口 + 无边框/置顶/托盘
- 打包：PyInstaller onedir，Python 与依赖全部内置，评委机器无需环境
- 配置：core/guga_paths.py 统一解析用户可写目录，原子写 + 回读校验
- 自检：core/env_check.py 真实探测（不是“理论上可用”）
- 桌面执行：pyautogui / pywin32 / UIA / 截图定位
- 软件发现：core/adapters/app_registry.py 按优先级解析启动路径
  （用户手动指定 > MCP 自报 > 注册表/开始菜单/常见目录/PATH）；
  声明清单在 core/adapters/apps/*.json
- 外部工具：core/adapters 下的豆包、WorkBuddy、JoyCode 适配器，
  统一回执与失败码
- 语音：sounddevice + vosk（中文模型不随包；首次使用需联网下载约 40MB，
  入口：GUGA-Desktop.exe --download-vosk-model，默认走国内镜像约 8 秒完成；
  不承诺离线语音开箱可用）
- 云端（可选）：管家派单、跨设备；不配置不影响本地功能

五、目录结构
----------------------------------------------------------------

压缩包根目录：
  GUGA-Desktop\          程序目录（exe + _internal）
  使用说明.html          完整说明
  使用说明.txt           纯文本兜底
  安装说明.txt           从解压到第一次用起来
  作品介绍.txt           本文件

用户目录（不在安装目录里）：
  %LOCALAPPDATA%\GUGA\ai_config.json     对话配置（含 Key）
  %LOCALAPPDATA%\GUGA\runtime\           运行数据（工作区、证据、安装建议）
  %LOCALAPPDATA%\GUGA\deliverables\      交付物
  %LOCALAPPDATA%\GUGA\app_reports.json   软件自报的安装路径（MCP）
  %LOCALAPPDATA%\GUGA\logs\startup.log   启动日志（设 GUGA_HOME 时在 %GUGA_HOME%\logs\）

----------------------------------------------------------------
六、常见问题
----------------------------------------------------------------

问：没有 API Key 能演示吗？
答：能进桌宠、能看自检、能用本地功能；对话和派单需要先在向导里填 Key 并测试连接。

问：软件装在 D 盘或别的目录，咕嘎找不到怎么办？
答：让软件连一次咕嘎的 MCP（配置见使用说明 8.5 节），调用 report_app 自报 exe 路径；
    咕嘎记住后以后直接启动。也可以手动设 GUGA_<软件> 环境变量，优先级最高。

问：没装豆包/WorkBuddy/JoyCode 会怎样？
答：会明确提示“本机没装”，并给出安装位置和下一步话术，不会代写冒充。

问：我只配了 MCP，没填模型 Key，咕嘎用的是谁的 API？
答：谁的都不用。没有任何内置、试用或赠送的 Key；没填 Key 时对话、拆任务、
    写回执、云端派单这些需要模型的路径都会明确提示“未配置模型”，
    不会偷偷发往任何默认端点，也不会借用别人的凭据。
    接入 MCP 只让咕嘎知道软件装在哪，不等于模型可用。

问：为什么有时候提示“没有真实工具调用回执”？
答：系统检测到只有模型文字、没有真实工具成功记录，按产品约束拒绝交付；重新派单即可。

问：安装目录只读能跑吗？
答：能。配置、日志、交付物都写到用户目录；安装目录不写入。

问：会收集隐私吗？
答：默认只在本机运行；只有你配置的模型接口和可选云端监工会联网。

----------------------------------------------------------------
七、能力边界（如实说明）
----------------------------------------------------------------

- 真机派单依赖目标软件已安装、已登录、窗口可正常显示；环境不满足时会明确失败。
- 缩放非 100% 时点击定位可能偏移，演示建议 100%。
- 复合任务串联与模型入口仍在收尾，本包以当前可用链路为准。
- 2560×1440 分辨率本机未适配，验收结论为“不适用”。

----------------------------------------------------------------
八、模型凭据排障与云端入口（20261110q）
----------------------------------------------------------------

模型报 401/403 时，本版不再笼统说“Key 问题”：
  - 读取/保存 Key 时自动去 BOM、零宽字符与首尾空白；中间夹空格/换行会拒绝发送；
  - 失败文案带“长度 + 前四 + 后四 + 来源”，方便和上一份能通的配置对比；
  - 按“Key 无效 / 无模型权限 / 额度不足”三类给不同的下一步；
  - 设置页新增「验证 Key（直连/系统代理）」，两条链路各发一次真实请求，
    只显示模式、状态码、耗时和打码片段。
云端账号改为桌宠右键常驻入口「☁ 云端账号（可选）…」，不填不影响本地能力，
只影响派单/跨设备；保存后可重新登录，不需要重启咕嘎。

----------------------------------------------------------------
九、启动自检不再污染派单输入（20261110r）
----------------------------------------------------------------

旧版启动自检会给 Windows 输入接口（SendInput）设一份全局类型签名且不还原，
之后派单真正按键时报
  ArgumentError: argument 2: TypeError: expected LP_INPUT instance instead of pointer to _INPUT
表现为「第 1/2 步（豆包）失败：… 缺什么：adapter_exception」，第一步即中断。
20261110r 起自检改用独立实例、不碰全局签名；派单侧每次按键前显式绑定自己的签名，
同一进程里“先自检、再派单”也不会互相污染。自检通过只代表自检项通过，不等于派单可用。

----------------------------------------------------------------
十、豆包 UIA 坐标与 OCR 失败分层（20261110s）
----------------------------------------------------------------

r 及更早的包在豆包 UIA 降级定位输入框时会报 KeyError: 2（归到 adapter_exception）；
20261110s 起坐标同时兼容字典 / 列表 / 元组，无效值按原逻辑跳过，不再中断。
同版本起，OCR 可用但识别到 0 行 0 字时单独报 ocr_empty（阶段“等待产物”），
与 adapter_exception 分开，便于判断失败发生在按键注入、OCR 还是产物等待层。
