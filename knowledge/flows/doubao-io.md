# 豆包 · 输入输出能力档案（v2.0）

- **档案ID**：doubao-io
- **软件**：豆包（Windows 桌面客户端）
- **实测版本**：147.0.7727.149（启动器 2.32.6）
- **实测时间**：2026-11-06（Asia/Shanghai），本机已登录
- **验证环境**：Windows 11 / 单屏 2560×1600 / 缩放 100%（**单环境验证**；150% 待补测）
- **口径**：入口位置一律"相对参照物"，不写像素坐标；凡没真做过的一律写【未验证】，不用推断填空。
- **本章重点**：豆包是四家里**唯一没有已验证"喂文件"入口**的软件。本章把 v2.0 指定的 5 条攻坚路径逐条结案。

## 一、文件喂入攻坚结论（v2.0 P0 逐条结案）

| # | 攻坚路径 | 本轮实测过程 | 结案 |
|---|---|---|---|
| ① | 输入栏「技能」「插件」有无文件入口 | 输入区右侧的 `…` 展开出两级菜单 `技能` / `插件`（`sense/imgs/doubao-menu_more-1.png`）；点 `技能` 打开的是**能力选择面板**（`推荐(2)` / `快捷功能(6)` / `办公(10)` 三组，条目全是"可视化 / 定时任务 / 用量 / 技能管理 / 计划 / PPT / 会议 / 录音转写"，底部只有 `搜索...`），**面板内没有任何"上传文件 / 添加附件"条目**（`sense/imgs/doubao-skill_page-1.png`）。`插件` 与 `技能` 同属能力面板层级。 | **无文件入口** |
| ② | 拖拽文件到对话窗口 | 未做（本轮未测，不做推断） | **未验证** |
| ③ | 「新工作任务(Ctrl N)」页里的附件入口 | 未做（本轮未打开该独立页） | **未验证** |
| ④ | 右侧「对话产物 / 对话资源」能否当接收落区 | 观察到的事实：右侧栏同时有 `对话产物`（带 `+`）与 `对话资源`（列出一串 **UUID 式文件名**：`C14AE719-206E-4687-A…`、`577C4B54-205A-42AA-E…`、`11E532B3-99BC-4BB6-A…` 等，带"查看更多"），下面还有 `技能`、`最近文件`。UUID 命名说明客户端会把会话内的文件资源统一收进"对话资源"索引里。**但这是"收到之后放在哪"，不是"怎么送进去"**；本轮没有从该面板反向喂入。 | **可作观察面，非入口；反向喂入未验证** |
| ⑤ | 兜底：降级为文本粘贴 | 输入框可直接粘贴长文本（占位「发消息或创建任务... / 使用技能 @ 添加资料」）；最长可粘字数**未测**。 | **可用，字数上限【未验证】** |

**另测一条**：`+` 按钮在**两套输入区**（工作/任务模式 `+｜本地电脑｜项目｜…｜自动`；对话模式 `+｜对话｜技能｜快速`）各点 1 次，**均无浮层、画面无变化**（2026-11-05 曾用像素差异法测得 DIFF=0.01%，两次结论一致）。

> **结案口径**：豆包桌面版当前**没有找到任何可验证的文件喂入入口**。执行器遇到"必须喂文件给豆包"的任务，应当：①先明确告诉用户"豆包桌面版喂文件这条我这儿没打通"；②降级为**把文件内容读成文本粘贴**（长文档先摘要/分段）；③或改派给有已验证文件入口的软件（元宝 `+ → 本地文件`、智谱「+」待复核）。**不要**反复点 `+` 假装在找。

## 接力特性

- **产物停在对话里还是能落成文件**：停在气泡里，已验证的拿取方式是 `复制`。会话级外送（分享链接 / 云盘）都未验证。**正因为豆包既进不来也出不去，"拿文件接力"这条上它是最弱的一环。**
- **两套输入区要认准**：`本地电脑` 是**授权本机操作的开关**，不是上传按钮；`…` 里是**能力选择器**，不是附件菜单。这两个是最容易被误当成"文件入口"的地方。
- **已知的坑**（现象 → 规避动作）：
  1. **现象**：点 `+` 无任何浮层（两次反复实测）。**规避**：别把 `+` 当上传键；要喂内容就走粘贴。
  2. **现象**：`本地电脑` 高亮后权限模式变化。**规避**：涉及删/覆盖的操作用户不点头就别开。
  3. **现象**：点左栏「最近」会**切走当前会话**（本轮误点「主对话」把窗口标题都改了）。**规避**：点前确认要点的是哪个会话；不想切就别碰左栏列表。
  4. **现象**：切到老会话出现「**暂不支持该消息类型**」。**规避**：这是老消息格式不兼容，不是崩了，继续用输入框。
  5. **现象**：窗口被别的应用盖住时，点击落到上层窗口（本轮实测豆包曾被智谱整窗覆盖，点击全部无效）。**规避**：先确认目标窗口在最前（标题栏高亮），再点。
  6. **现象**：屏幕上可能存在**全屏无标题的覆盖窗**（曾实测一例 rect 0,0 2560×1528，pid 属 explorer），吞掉点击表现为 DIFF≈0%。**规避**：先枚举窗口 rect，把占满全屏的无标题窗最小化，再操作。
  7. **现象**：点完窗口若标题改变，后续按旧标题找窗会 `WINDOW_NOT_FOUND`。**规避**：每次操作前重新取一次窗口矩形/标题。
