## 填写说明

0. **冷启动时的分辨率无关探测法（v2.0 新增，先读这条再填表）**

   探测一款陌生工具时，你拿到的机器可能不是 1920×1080@100%。**绝对像素坐标一律不能用**，按下面做：

   1. **先认窗口，再认位置**：用窗口标题（Win32 控件文字，跨分辨率完全稳定）确认"这是哪个应用、哪个窗口"，把窗口矩形当局部坐标系。之后写位置只用"相对参照物"：✓「输入框内部左下角圆形「+」，在「发送消息」占位文字左侧同行」；✗「点击坐标 (633,771)」。
   2. **先找文案，再找按钮**：靠**可见文案**定位——占位符、按钮文字、分组标题、弹窗按钮。文案是分辨率无关的；图标形状在缩放后会变形变小，不作为首选判据。
   3. **用"文案变化"验收动作，不用像素差异**：点完看占位符变没变、标题换没换、有没有新面板出现。深色界面文本像素占比低，像素差异常 <5%，会把"其实成功了"误判成失败（本知识库已两次踩到）。
   4. **缩放 >100% 时**：小字会糊，只认大标题/按钮文案；别硬读小字下结论，读不清就写【未验证】。
   5. **小屏 / 低分辨率时**：工具栏会折叠（例：豆瓣把 `技能`/`插件` 收进 `…`），按钮变少属正常。判据应写成"存在「…」或存在「技能」二者之一"，而不是死认某一个按钮。
   6. **多显示器**：先确认窗口完整落在某一块屏内再截图；窗口跨屏或贴边先最大化/拖回，否则截出来是半张。
   7. **登记环境**：每份档案必须写清"分辨率 + 缩放 + 显示器数"，并在多环境实测矩阵里逐项标"实测 / 未测 / 待补测"。**没拍的不许写成"已适配"**。

1. **每格填什么**
   - 表头六行：能从「关于」页直接抄的就抄；抄不到的版本号写「未取到」，不要编。
   - Output 表四行必须都在；没有的能力形态写「无此能力」，并在说明里写判断依据（点了哪个按钮、浮层第几项没有）。
   - Input 表三行必须都在；「支持格式」列照抄系统选择框的过滤串原文，不做概括。
2. **怎么标来源**
   - 每个数值开头打标记：`【实测】`（现场点出来的）/ `【官方】`（官网或应用内帮助写明的）/ `【未验证】`（猜的、没验证的）。
   - 同时在「数值与来源登记表」登记一行，来源类型只能填 `实测` / `官方文档` / `官方帮助` / `推测`。
3. **填不满怎么办**
   - 现场探测超过 8 步仍填不满 Output 形态 / Input 格式 / 入口位置三栏，按 `./cold-start.md` 第四节停手，反问少爷，不硬探、不猜填。
   - 存疑条目一律写 `【未验证】`，并在登记表证据栏写「待实测」；首次真机执行前先小步验证（见 `./cold-start.md` 第四节）。
4. **填完后**：本草稿走「经验候选 → 人工审核 → 入库」，下次同一工具直接命中 `./cold-start.md` 第 1 级。
