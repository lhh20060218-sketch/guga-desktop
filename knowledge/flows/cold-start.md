# cold-start：新工具冷启动协议

> 遇到知识库里**还没有能力档案**的工具时，按本协议查资料、落档案。
> 铁律：**猜永远是最后一档**。未走完第 1~4 级就直接摸界面试探的写法，一律返工。

---

## 一、五级信息获取优先级（顺序不可颠倒，拿到即停）

| 级 | 途径 | 怎么查 | 查到什么算合格 | 拿到即停的标志 |
|---|---|---|---|---|
| 1 | 本地知识库 | 在 `knowledge/flows/` 翻 `{slug}-io.md`；在 `knowledge/sense/` 翻 `{slug}-sense.md` | 能力表三张表列头齐全、关键字段（Output 形态 / Input 格式 / 入口）已填 | 命中 → 直接进入干活，不再查 |
| 2 | 官网帮助文档 / 使用说明 | 官网底部「帮助中心」「文档」「使用指南」入口；站内搜「上传」「导出」「格式」 | 有官方写明的支持格式、导出格式、字数/大小限制 | 拿到一份可对应到 Output/Input 行的官方说明 → 停 |
| 3 | GitHub | 项目 README / Wiki / Releases / 官方或社区 MCP server | README 里有 Features / Supported formats / Limits / API 任一相关段 | 拿到输入输出格式与限制的结构化说明 → 停 |
| 4 | 应用内「帮助 / 关于 / 新手引导」 | 打开客户端，翻「设置 → 关于」「新手引导」「帮助中心入口」 | 有现成的能力说明、快捷键、支持格式列表 | 补到第 2、3 级没拿到的字段 → 停 |
| 5 | UI 现场探测（最后手段） | 拿 `./generic-io.md` 空表，逐项现场探：能产什么 / 能收什么 / 入口在哪 | Output 形态、Input 格式、入口位置三栏填得上来 | 关键字段填齐 → 停；填不满见第四节 |

**唯一允许越级的情况**：少爷明说「这是内网小工具，外面没有资料」——可直接从第 4 级或第 5 级开始，但仍要在档案里写明「来源=实测」。

## 二、每级的具体鉴别方法

### 2.1 第 2 级：怎么确认是「官网」不是山寨站

- **域名与产品名对应**：产品名直接出现在主域名里（例：产品叫 X，官网就是 x.com / x.官方后缀）；出现「下载站 / 破解 / 绿色版 / 注册机」字样的直接排除。
- **站内互证**：「关于我们」页、备案号、官方下载页、帮助中心 URL 之间互相指向同一品牌主体；只有一个孤零零的下载按钮、没有公司信息的，不算官网。
- **URL 结构**：正规帮助中心通常是 `{官网}/help/...`、`{官网}/docs/...`、`{官网}/articles/...`，路径稳定可读；那种「点一下跳到陌生域名下载」的不是官网。
- **外部互证**：官方社媒账号、应用商店开发者页、公众号简介里挂的官网链接，与当前打开的域名一致；三处对不上，存疑标「待实测」。

### 2.2 第 3 级：GitHub README 怎么快速判断有没有输入输出说明

- **先扫这几个小标题**：`Features`、`Supported formats`、`Limits` / `Quotas`、`API`、`Roadmap`、`Usage`。有任一相关段落，就翻它——输入输出格式多半在里面。
- **看 Releases**：最近几个版本的 Release Note 里若写「新增支持导出 x 格式」「上传限制提到 xx MB」，直接抄进能力表，标来源=GitHub Releases。
- **看最近 commit**：README 三个月没动、但代码一周还在改 → 以代码与 Releases 为准，README 可能过期。
- **没有上述段落**：说明 README 偏营销，输入输出信息大概率没有，转第 4 级。

### 2.3 第 3 级：怎么识别一个仓库是不是该工具的 MCP server

MCP server 是**比 UI 操作可靠得多的结构化接入路径**，一旦存在，优先按它记录。鉴别四条：

1. **认官方 org**：仓库挂在工具官方组织名下（与官网同主体）最硬；社区个人写的算「社区 MCP server」，要标「社区」。
2. **认协议关键字**：README 里出现 `MCP`、`Model Context Protocol`、`tools` 清单、`server` 字样，且列了具体的 tool 名清单——这才是真 MCP server。只在标题蹭名字、正文没有 tools 清单的，不算。
3. **认官方文档互链**：工具官网文档的「集成 / Integrations」页挂了这个仓库链接——最硬的一条互证。
4. **看 star 与最近更新**：star 数与工具本身热度相称、最近半年有 commit；只认名字不认这四条，容易挂错山寨。

## 三、查到后怎么落库

- 按 `./generic-io.md` 同一张表的字段整理成 `{slug}-io.md` 草稿；
- 每条信息在「数值与来源登记表」里标来源类型：`官方文档` / `官方帮助` / `GitHub README` / `GitHub Releases` / `实测` / `推测`；
- 存疑条目（域名没互证上、README 与 Releases 对不上）在「说明/限制」单元格开头标 `【未验证】`，并在登记表证据栏写「待实测」；
- 落库时**不替软件编数**：没查到的限制一律写 `【未验证】`，不写「约 xx」装测过。

---

## 四、可信度规则与小步验证

- **可信度排序**：官网文档 ＞ GitHub README ＞ 应用内帮助 ＞ 第三方教程 / 博客。冲突时以高可信来源为准。
- **来源标「探测 / 推测」的条目，首次真机执行前必须先小步验证**：先做一次最小操作（例：上传一份最小的测试文件、让它产一张最短的图），成功才继续跑整链；失败即按 `./relay-rules.md` 第四节降级，或反问少爷。
- **何时放弃查询**：第 1~3 级都查不到有用信息（纯本地小工具 / 内网系统），才允许进第 5 级现场探测。
- **第 5 级探测上限**：现场探到第 8 步仍填不满关键字段（Output 形态 / Input 格式 / 入口位置），**立即停手**，如实反问少爷：「这个工具我没找到资料，需要您指点一下它支持什么输入、能产出什么。」不硬探、不猜填。

## 五、沉淀闭环

冷启动产出的 `{slug}-io.md` 草稿 → 走「经验候选 → 人工审核 → 入库」通道；入库后，下次同一工具直接命中第 1 级，不再走第 2~5 级。
