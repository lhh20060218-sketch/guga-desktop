# relay-rules：复合接力的通用推导规则

> 本文件教咕嘎**怎么思考**一条接力链，不教背哪条路。
> 所有判断都落到两件事上：①目标的最终产物落在「产物形态谱系」的哪一格；②各软件能力表（`./doubao-io.md`、`./kimi-io.md` 等）的 Output / Input 行各是什么。
> 禁止出现「用户说 X 就走 Y」式的关键词映射；下面只给判断框架。

---

## 一、判断：这个目标需要接力吗

### 1.1 产物形态谱系（差距就按这条轴量）

把任何产物都归到下面六格之一（允许相邻，但先按主格归类）：

| 格 | 形态 | 典型例子 |
|---|---|---|
| ① 纯文本 | 一段可复制的自然语言 | 摘要、文案、口播稿、问答对 |
| ② 结构化文本 | 带层级/字段/表格的文本 | Markdown 大纲、分镜表、卡片 JSON、周报骨架 |
| ③ 可下载文件 | 落成 docx/pdf/md/srt 等磁盘文件 | 一份 Word 周报、一个字幕文件 |
| ④ 图片 | png/jpg 位图，可下载 | 配图、封面、关键帧 |
| ⑤ 视频 | mp4，含时长与音轨 | 解说短片、教学视频 |
| ⑥ 可编辑工程 | 非成品、可在专业软件里继续改的工程文件 | 剪映工程、PPT 源文件、设计源文件 |

### 1.2 差距 → 步数的判断法

- 先定 **目标格**：少爷要的最终交付物落在谱系哪一格。
- 再定 **第一格**：手边第一个「顺手」工具（通常是已在对话里的那个）的 Output 行能直接产出哪一格。
- 两格之间隔几格，就是至少要走的步数。允许跨格合并（一个工具同时完成「②结构化」和「③文件导出」就算一步），但**不允许跳格假设**——第一个工具 Output 表里没有的格子，不能默认它能产。

**步数对照表：**

| 差距 | 步数 | 含义 |
|---|---|---|
| 目标格 = 第一格 | 0 步 | 直出，不开接力；只做一次对话 |
| 相邻一格（如 ①→②、①→④） | 1 步 | 换一个工具做一次转换即可 |
| 隔两格及以上（如 ②→⑤、①→⑥） | ≥2 步 | 必须排一条链，每步对齐一格 |

### 1.3 两个差距例子（不点名软件）

- **例 A（差一格，1 步）**：目标是「给我一份能直接发给客户的 docx 周报」。第一格是对话工具，Output 行只有「对话内文本，可复制」——它能写周报内容（①），但落不出 docx（③）。差距 = ①→③ 一格，解法：让它把内容写成 Markdown 文本，再用一个 Output 行有「文件类产物 docx」的工具吃进去导出，或由咕嘎自己把文本落成文件。
- **例 B（隔两格，≥2 步）**：目标是「把一份 PDF 做成 3 分钟解说视频」。第一格是对话工具，它读 PDF 能出文本（①），但目标是视频（⑤）——中间隔着「结构化分镜脚本（②）」这一格。差距 = ①→②→⑤ 两格，必须排两步：先出脚本，再交给 Output 行有「视频 mp4」的工具。

## 二、规划：传递链怎么排

### 2.1 选型原则（每一步都按字段对表选）

对链条上的每一步 i，选工具时只问两个问题：

1. **它的 Input 行能不能吃上一步 i-1 的产物？**——对上一步产物的形态/格式，查它 Input 表「支持格式」列与「大小/条数限制」列。
2. **它的 Output 行能不能产出下一步 i+1 所需的形态？**——查它 Output 表对应行的「形态」与「说明/限制」（时长、分辨率、字数上限、导出格式）。

两个都满足才入选；只满足一个，就这一步后面还要补一次转换。**不要凭「这个软件我熟」选**，要凭字段选。

**三个真实选型对比（写成可查字段，不写死结论）：**

- **对比甲：链条起点要吃一份长 PDF。** 候选 A 的 Input 行写「上传文件 pdf，单文件 xx MB」，接力特性栏注「长 PDF 解析弱」；候选 B 的 Input 行同样写 pdf，但接力特性栏注「长文档解析强、支持整份引用」。此时选 B——判据在「接力特性·处理上传文件的能力强弱」这一栏，不是名字。
- **对比乙：链条末段要产一段 3 分钟视频。** 候选 C 的 Output 行「视频」列写「时长上限 xx 秒，文生视频」；候选 D 的 Output 行写「图生视频，mp4 下载」。若上一步产物是一段脚本文本，C 直接吃文本更顺；若上一步已经攒了一组关键帧图，D 更顺。判据在 Output 行的「形态」列（文生 vs 图生），不是「谁更强」。
- **对比丙：中间要把脚本落成可二次编辑的工程。** 候选 E 的 Output 行只有「对话内文本，可复制」；候选 F 的 Output 行除文本外还追加了一行「工程文件，可导出」。目标格是谱系第⑥格（可编辑工程）时，必须选 F——判据在 Output 表有没有第⑥格那一行，不在它聊天聊得多顺。

### 2.2 传递形态：上一步产物走「复制文本」还是「落文件再喂」

**判断标准（逐条核对，命中任一即落文件）：**

- 下游工具要**按结构解析**这份产物（分镜表、JSON、表格、卡片字段），纯文本粘贴会丢结构；
- 产物要**保留版式**（标题层级、表格、代码块）；
- 产物体积**超出粘贴上限**（对照下游 Input 表「大小/条数限制」列）；
- 这份产物后面要**被多次复用**（喂给两个以上下游，或少爷要留底）。

**以上都不命中，且下游只吃纯文本、做的是语义改写**——走「复制文本」最省事。

**两者都能走时的优先级：优先落文件。** 理由：文件是「死」的，结构、字数、版式都不会因为复制粘贴而丢；而且文件可以回头改了重喂，不用重跑上游。唯一例外是产物本身就是一句话提示词、且下游只吃纯文本——那复制文本更快，不值得为一句话做导出。

### 2.3 格式转换点：谁来做转换（三条原则）

1. **上游工具能原生导出，就用它原生导出。** 查上游 Output 行「文件类产物」列写的格式；它能直接导出下游 Input 表支持的格式，就一步到位，不要中间转一手。
2. **转换成本低于重做，就由咕嘎自己改写。** 例：上游产出 Markdown，下游只吃纯文本——咕嘎自己剥掉 Markdown 符号即可，不必为这层转换再开一个工具。
3. **会损失结构的转换，必须在能力更强的工具侧做。** 例：把分镜脚本（结构化文本）喂给只吃纯文本的工具之前，要由一个「能解析表格」的工具先把脚本展平成口播稿，而不是咕嘎手工抄——手工抄必丢字段。

**转换后验收**：打开转出来的那一份，按清单看关键结构在不在——表格行列还齐不齐、分镜的「画面/口播/时长」三列有没有缺、文件能不能在下游工具里正常打开。看一眼，不在就重转，不进下一步。

## 三、反问：什么时候必须问少爷

### 3.1 三类动作的处理原则

- **不可逆 / 大消耗 → 必问**：生成视频耗额度、覆盖已有项目、删除内容、对外发布/发送。动之前先问，等少爷点头。
- **主观偏好 → 集中一次问清**：风格、数量、时长、分辨率、受众口吻。这些不定准了后面全白做，但也不要走一步问一步——在链条排好、第一锤要砸之前，**一次问完**。
- **有合理默认值 → 不问**：直接干，并在开工时一句话告知用了什么默认（例：「少爷，配图我先按 16:9 出，要别的比例随时说」）。

### 3.2 「一次问清」模板（最多 3 问，每问带默认值）

> 少爷，这条链路我理好了，开工前跟您对三件事：
> 1. **时长/数量**：成片按 3 分钟出可以吗？（默认 3 分钟，要 1 分钟或 5 分钟您说一声）
> 2. **风格/口吻**：解说偏「专业商务」还是「轻松白话」？（默认专业商务）
> 3. **分辨率/画幅**：按 16:9 横版出？（默认 16:9，发手机端可换 9:16）
>
> 您不回我就按括号里的默认走了。

超过 3 问就说明链条还没排清，回去重排，不要把选型难题甩给少爷。

## 四、降级：某环节不可用怎么办

### 4.1 先找「同输入同输出」替代

按能力表逐行筛，替代工具必须同时满足：

- **Input 行能吃上一步产物的同格式**（格式列对齐、限制列可接受）；
- **Output 行能给下一步所需的同一产物形态**（谱系同一格）；
- 限制列里的代价（时长上限、额度、条数）少爷能接受。

三条全满足，就把这一步的工具换掉，链条其余环节不动。

### 4.2 找不到替代就如实上报

不硬撑、不绕路、不假装做完。上报三句话：

1. **停在哪一步**：链条排到第几步断了（例：「脚本已经写好，卡在『产出视频』这一步」）；
2. **缺什么**：哪个能力表的哪一行找不到（例：「手边没有 Output 行带『视频 mp4』的工具，或它的时长上限不够 3 分钟」）；
3. **下一步要少爷给什么**：是要新开一个工具、还是放宽时长上限、还是先出一版不带视频的文本稿。

降级后产物形态变了（例：视频没做成，先交了脚本文本），必须在交付时明说，不能把中间稿当成品交。
