## 一、界面状态枚举（只用这 8 个标准值，程序按字符串匹配，不得自造/改大小写）

| 状态值 | 本机是否出现 | 一句话判定要点 | 截图 |
|---|---|---|---|
| `empty_chat` | 通用文件，不适用 | 输入区在，但没有任何已发出的消息气泡，可直接开始一次新会话 | 无（通用文件不绑定具体软件截图） |
| `ongoing_chat` | 通用文件，不适用 | 已有连续的用户/AI 消息气泡停在屏幕上，输入区仍在底部待命 | 无（通用文件不绑定具体软件截图） |
| `workspace_picker` | 通用文件，不适用 | 主操作区是"项目/工作空间/选择/最近项目"之类的列表页或卡片墙，还没进任何一个具体项目 | 无（通用文件不绑定具体软件截图） |
| `history_sidebar` | 通用文件，不适用 | 当前屏幕不是对话，而是左侧/顶部铺开"历史/最近/会话"列表，正处在挑选旧会话的状态 | 无（通用文件不绑定具体软件截图） |
| `dialog_popup` | 通用文件，不适用 | 有遮罩层/模态框挡住主操作区，主界面点不动 | 无（通用文件不绑定具体软件截图） |
| `unknown` | 通用文件，不适用 | 上面各条特征都对不上，拿不准 | 无（通用文件不绑定具体软件截图） |
| `loading` | 通用文件，不适用 | 画面是骨架屏/转圈/大片空灰，**没有可读的界面文案**，且持续 60 秒以上不变 | 无 |
| `ai_creation_page` | 通用文件，不适用 | 界面是"图片/视频创作"落地页（创作标题 + "描述你想生成的图片/视频"类占位 + 模型/比例/清晰度选项），**不是对话页** | 实例见 `imgs/yuanbao-ai_creation_page-1.png` |

表下说明：本文件为通用兜底，"本机是否出现"一列统一写"通用文件，不适用"——这 8 个状态是**任何一款对话/创作类软件都应能落进去的标准槽位**，某款具体软件缺哪个（例：无项目概念就没有 workspace_picker），在该软件自己的 `*-sense.md` 里说明。

## 二、每种状态的视觉特征（给视觉模型看的"看到什么就判成什么"）

> 互斥优先级（多个特征同时成立时，从上往下先命中哪个判哪个）：
> **`dialog_popup` > `loading` > `workspace_picker` > `ai_creation_page` > `ongoing_chat` > `empty_chat` > `history_sidebar` > `unknown`**
> 理由：挡路的弹窗最影响操作，必须最先处理；加载中先等一等别误判成空页；能选项目就先确认选哪个，别贸然开新会话；创作页"看着空"但不是对话页，必须早于 empty_chat 判出来；有旧消息就别误判成空会话。

### empty_chat（空会话）
- 输入框（底部输入区）清晰可见、**是空的**，占位符是"有什么可以帮你 / 发消息 / 输入指令"之类。
- 输入框上方**没有任何一条已发出的消息气泡**（连"你好"都没有）。
- 屏幕中间往往是欢迎语 / 几个推荐问题卡片 / 一个大 Logo——但这些是装饰，只要没有历史气泡就判 empty。

### ongoing_chat（进行中的会话）
- 输入框上方有**连续的用户气泡 + AI 回复气泡**，能看出一段已经聊过的内容。
- 输入框仍在底部待命，占位符变成"继续对话 / 输入消息"样式（不再是全新欢迎态）。
- 可能左侧或抽屉里高亮着一个会话标题——这是"接着上次聊"的强信号。

### workspace_picker（工作空间/项目选择页）
- 主操作区铺满**项目/工程卡片墙或列表**，卡片上写着项目名、缩略图、修改时间。
- 顶部或显著位置有"新建项目 / New Project / 选择项目 / 最近项目"之类的区块标题。
- 此时**还没有任何一个项目被打开**，没有时间线/对话流——主任务区就是"选一个进去"。

### history_sidebar（历史会话侧栏）
- 一条**左侧栏或顶部抽屉**里是一长串历史会话列表（每行一个旧对话标题/时间）。
- 当前主区是空的、或只是欢迎页，并没有正在进行的对话气泡。
- 重点：列表在、但当前没在任何对话里 = history_sidebar；一旦点开某条进去、出现消息气泡，就升级成 ongoing_chat。

### dialog_popup（弹窗/推广/更新提示挡路）
- 主界面之上有一块**半透明遮罩**，主操作区变暗/点不动。
- 遮罩中央或右下角浮着一个**模态小窗**：推广、更新提示、登录引导、权限申请、会员开通、新手引导都算。
- 窗口上通常有"×"、"关闭"、"稍后"、"跳过"、"不再提示"等按钮——见第五节关闭顺序。

### ai_creation_page（AI 创作页，"看着空、其实不是对话页"）
- 主区是**创作落地页**而不是对话：大标题多是"开始你的创作吧 / 开始创作 / 描述你的想法"，**没有"今天能帮你做什么"这类对话欢迎语**。
- 输入框占位是"**描述你想生成的图片 / 视频**"这类**生成描述**，不是"发送消息 / 处理复杂工作"。
- 输入框上方或旁边有**模型 / 比例 / 清晰度**选择（例：`Hy Image3.5 preview`、`智能比例`、`1.5K`），下方是**示例作品卡片墙**。
- 关键后果：**此页的文件入口与对话页不同**（实测元宝创作页的「+」点不出"本地文件"）。在这页找对话页的文件入口永远找不到，必须回聊天页。
- 实例截图：`imgs/yuanbao-ai_creation_page-1.png`。

### loading（加载中占位页）
- 画面是**骨架屏 / 转圈 / 大片空灰**，读不到任何可操作文案，输入框也没出现。
- 判定门槛：**持续 60 秒以上不变**才判 `loading`；不到 60s 的短暂空白按 `unknown` 原地等待，别急着下结论。
- 实测口径（来自 Kimi 案例）：客户端卡在"工作区正在准备中"90 秒以上即属此类，执行器要**能等一等**，不要一看到空白就判定软件坏了。
- 超过 60s 仍 loading：按第四节固定话术反问用户（可能要登录/要会员）。

### unknown（认不出）
- 上面各条特征都凑不齐：既没消息气泡、也没项目墙、没侧栏、没遮罩，但你也说不清这是哪。
- **宁可判 unknown 反问用户，也不要硬猜**（红线）。

## 三、会话/项目结构说明（没有专门档案时的通用观察顺序）

没有这款软件的专门档案时，按这个固定顺序看，自己推断结构：

1. **先看左栏**：左边有没有一条竖栏？里面是"历史会话列表"还是"项目/素材库"还是"无"？
   - 列表项长什么样（一行标题 + 时间？一个卡片缩略图？）。
2. **再看顶部**：顶部导航/标签里有没有"工作空间 / 项目 / 最近 / 新建"？顶部和左栏是不是同一套东西。
3. **最后看输入区**：屏幕底部有没有输入框？输入框上方现在有没有消息气泡？
4. **推断"这是项目还是随手对话"**：
   - 主操作区是**卡片墙/列表、没有聊天流** → 这是项目/workspace 制（workspace_picker），得先进一个项目才能干活。
   - 主区直接就是"输入框 + （可能有的）欢迎语"，历史只藏在侧栏 → 这是随手对话制，开聊就开新项目。
   - 两者混合（侧栏历史 + 主区对话）→ 历史是"会话记录"，当前主区在聊哪条就是哪条。
5. **新建入口的通用找法**：找"＋ / 新建会话 / New chat / 新对话 / ＋ 新建项目"这类按钮；不同页面（首页 vs 项目页）位置可能不同，先记下看到的那一处。

## 四、反问话术模板（2~3 条，通用版）

统一格式：称呼「少爷」，一句话一个决策点，给两个明确选项，不问开放题。

```markdown
1. **触发**：检测到 ongoing_chat，且当前任务和这个旧会话看不出明显承接关系。
   **话术**：「少爷，这个软件里还挂着一个进行中的会话，我是接着它往下做，还是给您开个全新会话？」

2. **触发**：检测到 workspace_picker，且屏幕上有多个项目/最近项目卡片，不知道要进哪一个。
   **话术**：「少爷，现在停在项目选择页，这里有好几个项目——我是打开最近那一个接着弄，还是新建一个项目从头来？」

3. **触发**：检测到 unknown，界面认不出、不敢贸然点。
   **话术**：「少爷，这个窗口我拿不准现在是什么状态——您是想让我先把界面上清一下（关弹窗/回首页），还是您直接告诉我接下来点哪里？」

4. **触发**：检测到 `ai_creation_page`（固定话术，v2.0 指定）。
   **话术**：「少爷，{app}开在了图片创作页——这单要聊天处理，还是就在创作页做图？」

5. **触发**：检测到 `loading` 超过 60s（固定话术，v2.0 指定）。
   **话术**：「少爷，{app}还在加载，可能要您登录一下，我先等等还是您处理完叫我？」
```

## 五、弹窗与干扰处理（通用识别与关闭顺序）

| 弹窗名称/类型 | 触发时机 | 长什么样（按钮文案原文） | 怎么关（位置+文案） | 本机是否复现 |
|---|---|---|---|---|
| 遮罩模态框（推广/活动） | 打开软件、切后台回来、首次进功能 | 半透明遮罩 + 居中小窗，常有大图 + "立即参与/领取" | 找小窗右上角"×"或底部"关闭/跳过/稍后" | 通用文件，不适用 |
| 更新提示 | 启动时、版本检查后 | "发现新版本 V x.x"，按钮"立即更新/下载更新" | 优先"稍后/以后再说/取消"；**绝不盲点"立即更新"** | 通用文件，不适用 |
| 会员/开通引导 | 点了付费功能、首次用高级能力 | "开通会员/立即开通"弹窗，带价格 | 找"×"或"暂不开通/取消"；**绝不盲点"立即开通/付费"** | 通用文件，不适用 |
| 新手引导/气泡指引 | 首次打开 | 高亮某按钮 + 箭头气泡 + "下一步/知道了" | "知道了/跳过/不再提示" | 通用文件，不适用 |
| 右下角浮层/消息红点 | 常驻或定时弹出 | 小卡片浮在右下角，"消息/活动" | 浮层上的"×"或"忽略" | 通用文件，不适用 |
| 系统级权限申请（麦克风/通知/文件） | 首次用对应功能 | 系统对话框，"允许/拒绝" | 按任务需要点；拿不准就"拒绝/稍后" | 通用文件，不适用 |

**通用关闭顺序（固定照做）**：
1. 先找显式关闭控件：**「×」「关闭」「稍后」「跳过」「知道了」「不再提示」**——优先点这些。
2. 其次找**「取消」/「返回」/「暂不」**这类不改变软件状态的按钮。
3. 再不行按 **Esc** 兜底关闭模态框。
4. 都关不掉 → **如实上报**，把弹窗长什么样、上面有哪几个按钮报给用户，让用户决定。
5. **红线**：不许盲点"立即更新 / 立即开通 / 立即购买 / 立即领取"这类会改变软件版本、花钱、或跳转到外部的按钮——这类必须先问。

**关闭后必做复核**：关完任何弹窗，都要再看一眼主界面是否恢复可操作（遮罩是否消失、输入框/项目列表是否能点），确认 `dialog_popup` 解除、回到正确状态再继续干活。

**一类"看不见的干扰"（本机实测）**：屏幕上可能存在**全屏、无标题、看不见内容的顶层窗口**（实测一例属豆包进程，rect 0,0 2560×1528），它会吞掉发往其它窗口的点击，表现为"鼠标点了没反应、像素差异 ≈ 0%"。识别与规避：① 用 `WindowFromPoint` 探测点击坐标实际命中哪个窗口，若不是目标任务，说明有覆盖窗；② 把目标窗口 `SetWindowPos(HWND_TOPMOST)` 置顶后再点，用完再 `HWND_NOTOPMOST` 还原；③ `SetForegroundWindow` 返回 False 属 Windows 前台锁，改用"物理点击目标窗口标题栏"激活。这套动作属于环境修复，不算改变用户软件状态。

## 六、页面判别锚文本表（通用版）

判定优先级：**控件文字 > 屏幕可见文字 > 视觉特征**。控件文字（Win32 窗口/子窗口标题）完全不受分辨率与缩放影响，永远是第一选择。

| 状态 | 锚文本（判定用，逐字） | 出现位置 | 获取方式 |
|---|---|---|---|
| `empty_chat` | `发送消息` / `有什么可以帮你` / `发消息或创建任务` | 输入框占位符 | 屏幕可见文字（占位符不算 Win32 控件文字） |
| `ongoing_chat` | `输入问题或任务` / `继续对话` + 任一历史消息文本 | 输入框占位 + 消息区 | 屏幕可见文字 |
| `workspace_picker` | `选择项目` / `新建项目` / `最近项目` / `选择分组` | 主区标题或按钮 | 屏幕可见文字 |
| `ai_creation_page` | `开始你的创作吧` / `描述你想生成的图片` / `描述你想生成的视频` | 主区大标题 / 输入框占位 | 屏幕可见文字 |
| `history_sidebar` | `最近` / `历史` / `新建对话` / `新建任务` | 左栏列表标题与首行按钮 | 屏幕可见文字 |
| `dialog_popup` | `我知道了` / `稍后` / `跳过` / `暂不添加` / `关闭` | 弹窗按钮 | 屏幕可见文字 |
| `loading` | 无稳定锚文本（以"60s 无可读文案"为判据） | — | 视觉 + 计时 |
| 全局归位 | 应用名（窗口标题，如 `元宝` / `智谱清言` / `豆包`） | 标题栏 | **控件文字**（Win32 标题，优先级最高） |

> 跨软件实测提醒：**Chromium 系客户端（豆包/元宝/智谱/Kimi）页面内元素一般读不到 Win32 控件文字**，只有窗口标题可读。因此"控件文字锚点"在这类软件里通常只能用于**确认打开了哪个应用/哪个窗口**，页面级判定仍要靠屏幕可见文字（OCR/视觉）。别假设能读到页面控件标题。

## 七、冷启动时的分辨率无关探测法（v2.0 新增）

换一台机器（不同分辨率、不同缩放、多显示器）时，**绝对坐标全部作废**。按下面顺序做，不要抄任何像素坐标：

1. **先定窗口，不定像素**：用窗口标题（控件文字）找到目标窗口，取其外框矩形作为"局部坐标系原点"。之后所有位置都用**窗口内相对比例或相对参照物**表达。
2. **再找参照物，不找坐标**：把界面元素写成"相对谁、在哪一侧、第几行"，例如
   - ✓「输入框内部左下角的圆形「+」，在「发送消息」占位文字左侧同行」
   - ✗「点击 (633, 771)」
3. **用文字确认命中的是谁**：点完一个元素后，用**它该引起的文案变化**验证（占位符是否变、标题是否换、是否出现新按钮文案），而不是用像素差异百分比。深色界面下文本占比低，像素差异常常 <5%，会让"其实成功了"被误判成失败。
4. **缩放不是 100% 时**：字号会变小/变糊，OCR 阈值要放宽；若小字不可读，**只认大标题与按钮文案**做判定，别硬读小字。
5. **多显示器/窗口贴边**：窗口可能落在副屏或被裁，先确认窗口矩形完整落在某一块屏内，再截图；被裁就先把窗口拖回主屏或用最大化。
6. **1080p 等小屏**：工具栏会**折叠**成「更多」菜单，按钮变少属正常现象——判定时以"是否存在「更多」"为准，不要因为找不到原按钮就判 unknown。
7. **禁止**在知识库、脚本、话术里写死任何绝对坐标；如确需记录，只写在"环境备注"里并注明"仅该机该分辨率有效"。
