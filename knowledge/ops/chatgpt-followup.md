# 剧本ID：ops-chatgpt-followup-002

## 软件
ChatGPT（本机未安装桌面客户端，以网页版 chatgpt.com 为准；桌面端入口待真机核对）

## 动作目标
在同一个已开启的会话里继续追问，让后续回答延续上一轮上下文，而不是另起炉灶。

## 前置条件
- 少爷已按 ops-chatgpt-ask-001 打开 chatgpt.com 并拿到过至少一段完整回答。
- 浏览器仍停留在那条对话页面，没点过「New chat / 新对话」。
- 官方说明：登录后对话才会被保存；未登录刷新可能丢上下文。

## 步骤序列

1. **元素特征+动作+等待判据**
   - 元素特征：页面底部/中部的同一个大文本输入框。
   - 动作：先扫视左侧会话列表，确认高亮的正是刚才那条对话（标题通常取首句前几个字，确切命名规则待真机核对）。
   - 等待判据：上方对话流仍能看到上一轮的提问与回答，没有被清空。

2. **元素特征+动作+等待判据**
   - 元素特征：同一输入框（与上一步是同一个，不在左侧另开新窗口）。
   - 动作：单击输入框，键入追问，例如"那上一条里的第 2 点再展开讲讲"。
   - 等待判据：追问文字完整显示，发送按钮亮起。

3. **元素特征+动作+等待判据**
   - 元素特征：发送按钮（向上箭头图标）。
   - 动作：点击发送或回车。
   - 等待判据：少爷的追问追加在原对话流下方，而不是页面顶部新开一段；回答开始流式输出。

4. **元素特征+动作+等待判据**
   - 元素特征：上一轮自己发出的那条提问。
   - 动作：若追问写错了，把鼠标悬停在自己这条消息上，官方说明会出现铅笔（编辑）图标，点它可改写后重发；也可对某条回答点重试图标"再试一次"。
   - 等待判据：编辑后该条消息文字更新，下方生成对应新回答。

5. **元素特征+动作+等待判据**
   - 元素特征：顶部或输入框附近的模型/模式选择器（官方称 model picker，出现 Instant / Medium / High 等档位名称）。
   - 动作：如追问更费脑，可点开选择器切到更高档位；不需要则保持默认。
   - 等待判据：选择器文字变为所选档位，新回答按该档位生成。

6. **元素特征+动作+等待判据**
   - 元素特征：回答正文。
   - 动作：静候输出。
   - 等待判据：文字停止逐字增加，操作按钮（复制/点赞等）出现，且回答里能引用上一轮的内容，即视为上下文衔接成功。

## 成功判据
追问被追加在原对话之内，回答明显承接上文（提到"刚才/上一条"相关内容），左侧会话仍为同一条而非新增。

## 异常处理
- 少爷若发现回答像失忆、完全不记得上文：多半是误点了「New chat」开了新会话，管家会回到左侧列表点开原会话继续，并提醒少爷别再点新对话。
- 若追问发出去一直转圈：管家先等十来秒，仍不动就点回答旁的重试，不行再重发一次。
- 若少爷想要完全无关的新问题：管家会引导点「New chat」另开，避免旧上下文污染。
