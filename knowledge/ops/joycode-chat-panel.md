# joycode-chat-panel：打开 JoyCode AI 聊天面板并核验状态

- **剧本ID**：joycode-chat-panel
- **软件**：JoyCode 桌面客户端（Windows，D:\JoyCode，VS Code 系 Electron 架构）
- **动作目标**：在 JoyCode 主窗口内打开/确认右侧 AI 聊天面板（Coder 会话区），为 /guga-run 派单提供可输入的对话入口。

## 前置条件

1. JoyCode 主窗口存在且非最小化（窗口标题形如 `xxx - rengongzhineng - JoyCode`）。
2. guga MCP Server 已连上当前 JoyCode 实例（进程列表里有 `core/adapters/guga_mcp_server.py`，且由当前实例拉起；旧实例的 MCP 子进程会随实例退出而死，重启后需确认新 PID）。
3. 执行方进程已声明 DPI 感知（`ctypes.windll.shcore.SetProcessDpiAwareness(2)`），否则 UIA 物理坐标与 GetWindowRect 逻辑坐标错位，比例换算越界。

## 步骤序列

1. **元素特征**：标题栏 CheckBox「切换JoyCode侧栏 (Ctrl+Alt+B)」，patterns 含 InvokePattern/TogglePattern。**动作**：UIA `act(invoke, name='切换JoyCode侧栏 (Ctrl+Alt+B)')`，窗口不在前台也能生效，不抢焦点。**等待判据**：UIA 快照右侧出现 `type=Document, name='Coder'` 元素（面板展开的标志物）。
2. **备选**：窗口已在前台时可直接发 `Ctrl+Alt+B` 热键；窗口不在前台发快捷键会被系统吞掉，不得依赖。**注意**：invoke 和热键都是"翻转"语义，发一次验一次，连发两次等于没发。
3. **状态核验（结构信号，优先于 OCR）**：快照里存在名为 `Coder` 的 Document = 面板开；不存在 = 面板关。OCR 判面板状态只在窗口前台时可靠——PrintWindow 对后台 webview 常截出空白/黑图，会误判"面板已开"为"关"，再按快捷键就把面板关掉了（历史事故根因）。
4. **输入框定位**：
   - 欢迎/空会话状态：输入框在面板**垂直中部**（约窗口比例 x=0.84, y=0.50），占位文字含"通过"/"添加上下文，"/"使用快捷指令，"!"切换历史输入"；模型芯片（如 `qwen3.8-flash`）与模式芯片（如"问题修复"）在输入框正下方。
   - 会话进行中：输入框回到底部条带。
   - **危险**：不要用 UIA `focused` 命中 Edit 就认定是聊天输入框——JoyCode 聊天输入在 webview 内不暴露为 Edit，`focused` 命中的 Edit 几乎必然是**代码编辑器**，此时 Ctrl+A+Delete 会清空编辑器里打开的文件（2026-11-07 实测发生过）。输入前必须截屏确认光标在右侧面板内。
5. **投递核验**：剪贴板粘贴命令后回读一致，回车；成功标志是"最近任务"列表出现该命令条目（带时间戳），且对话区出现用户气泡。

## 模式芯片切换（问题修复 → 编码等，2026-11-07 实测）

派单进"最近任务"但无回执时，先确认模式芯片不是"问题修复"，按下述路径切到"编码"（默认可跑工具调用/代码生成的智能体模式）。

1. **元素特征**：输入框正下方芯片行，左起第一个是模式芯片（当前值），其右是模型芯片（`qwen3.8-flash`）。芯片在 webview 内，**UIA 不暴露**（快照只有窗口级元素如 completion-icon），只能坐标点击，且 `_act` 要求窗口在前台：先 `_activate(hwnd, allow_steal=True)`（用户 3 秒内有键鼠输入会被拒）。
2. **关键坑（必须显式比例坐标）**：`ui._act('click', x, y)` 默认**不是**比例坐标空间，x=0.66 会被当作 0.66 物理像素点窗口左上角，表现为"点了没反应"。必须 `ui._act('click', coordinate_space='ratio', x=.., y=..)`（参照 `_click_input`）。
3. **比例必须现算**：`_activate` 可能把最大化窗口还原成小尺寸（实测 1938×1048 → 1500×950），旧比例全部失效。每次操作前 grab 当前帧、OCR 芯片行重新取中心。实测（1500×950 帧）：模式芯片"问题修复"OCR 逐字命中（问/题/修/复），中心比例 ≈ (0.659, 0.578)。
4. **动作**：点芯片 → 下拉**向上**展开 → 等 0.9–1.2 秒 → 截屏+OCR 核验。下拉选项（内置智能体）：**编码 / 架构图设计 / 问题修复 / 问答 / 规约编程**；（用户智能体）：创建智能体。选"编码"行实测比例 ≈ (0.655, 0.294)。
5. **成功判据**：芯片带（y 0.55–0.60）OCR 文字由"问题修复"变为"编码"，下拉关闭。
6. **异常处理**：
   - 切到"编码"后输入框可能**自动填充**基于当前打开文件的提示词草稿（实测出现 "Act as a technical systems analyst … task ID ZZZ7QXQ7A"）。这不是自动化残留：不得清空、不得提交、不得对它发 Ctrl+A/Ctrl+C 回读（会破坏用户/并行会话资产）。重发派单前必须确认输入框为空，有草稿=面板不空闲，禁止自动投递。
   - 收尾恢复最大化用 `ShowWindow(hwnd, SW_MAXIMIZE)`；原前台窗口若已关闭，`SetForegroundWindow` 报 error 2，可忽略。

## 成功判据

快照存在 `Coder` Document；输入框获得焦点且粘贴回读一致；回车后"最近任务"或对话区出现该条命令。

## 异常处理

- **派单进了历史但无回执、无产物**：先查聊天面板**模式芯片**——"问题修复"模式不跑代码生成/工具调用工作流，按上文「模式芯片切换」切到"编码"再发；再查 guga MCP Server 进程是否挂在当前 JoyCode 实例上（旧 PID 死亡=工具不可用，智能体会静默失败）。
- **UIA 执行器响应超时**：uia_service 是单 worker 串行队列，超时请求仍会被执行，面板会被"迟到"翻转。禁止盲目重试 toggle；每次操作后等 15–20 秒用结构信号核验实际状态。
- **面板显示欢迎页但历史里有未看的会话**："最近任务"条目点击可恢复会话；点不开时不要反复点，改用新会话直接投递。
- **高风险边界**：本剧本的编辑器焦点误判路径可破坏用户正在编辑的文件；任何"清空输入框"动作前必须确认焦点在聊天面板内，不得对编辑器发 Ctrl+A/Delete。
