# cursor-followup：同一 Chat 会话内基于上文追问

- **剧本ID**：cursor-followup
- **软件**：Cursor 桌面客户端（Windows，版本 3.27.12）
- **动作目标**：在不新建会话的前提下，就上一条回答继续追问，让模型带上文上下文作答。

## 前置条件

1. 剧本一已成功跑完：Chat 面板里已有至少一轮"提问 → 回答"历史。
2. 没有点过 "New chat"（官方快捷键 `Ctrl+N`），也没有关过 Chat 面板（关了重开默认回到最近会话，但保险起见别关）。
3. 当前模型没有在生成中（否则追问会排队而不是立刻发）。

## 步骤序列

1. **元素特征**：Chat 面板底部同一个输入框（与剧本一第 2 步是同一个框，**不是**新开的框）。**动作**：确认焦点在输入框后，直接敲追问，例如"你刚说的缓存逻辑再展开讲一下，举个具体例子"。**等待判据**：文字进了输入框，上一轮的回答仍留在历史区上方未消失——这证明上下文还在。
2. **元素特征**：`Enter`（官方：Queue message）。**动作**：按 `Enter` 发送。**等待判据**：新提问作为又一条用户气泡追加到历史末尾，模型开始流式输出，且回答开头能看出它引用了上一轮内容（比如复述"关于刚才那个缓存…"）。
3. **元素特征**：模型回复流。**动作**：静等。**等待判据**：回复结束、无截断。
4. **（可选）跨轮翻历史**：若想问"第三轮那个方案里提到的文件路径"，用官方快捷键 `Ctrl+[`（Previous chat）和 `Ctrl+]`（Next chat）在相邻会话间切换；确认目标会话后回到该会话输入框继续问。**等待判据**：面板顶部标题随 `Ctrl+[`/`Ctrl+]` 切换成另一段对话。

## 成功判据

历史区里从上到下依次是"第一轮问题 → 第一轮回答 → 第二轮问题 → 第二轮回答"，且第二轮回答明显引用了第一轮的术语，证明上下文被正确携带。

## 异常处理

- **模型好像忘了上文（回答像在重新答第一问）**：少爷，这是上下文窗口被挤掉或你误按了 `Ctrl+N` 开了新会话。按 `Ctrl+[` 往回翻一个会话，找到有第一轮历史的那条，回到该会话再问；或在追问里显式带上关键词，如"基于你上一条回答中提到的 X 机制……"。
- **追问发出去后排队不动**：上一轮还在生成。等它出完，或按 `Ctrl+Shift+Backspace` 取消后重发。
- **追问超过 10 轮后回答质量明显下降**：长会话上下文漂移。按 `Ctrl+N` 开新会话，用 `@`（官方：@-mentions）把关键文件 / 上一轮结论重新挂进上下文，别在旧会话里硬续。
- **误按 `Ctrl+N` 新开了会话**：立刻 `Ctrl+[` 切回上一个会话，新会话里的那条追问可以不管或按 `Ctrl+W`（Close chat）关掉。
