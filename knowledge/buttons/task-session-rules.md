# 任务级会话隔离规则（KB8 v4 · 2026-11-06）

- **文件**：`buttons/task-session-rules.md`
- **定位**：不是新实测，是把库里已有的「新对话」「新建任务」「AI创作」三类事实**串成一条可执行的任务级规则**。正文凡引用按钮与锚文本，均指回已有档案编号。
- **适用软件**：本规则面向全部五个已建档桌面客户端（元宝 / 智谱清言 / 豆包 / WPS / 剪映），逐软件的具体锚文本以各自档案为准。

---

## 一、新任务 = 新会话

- **本篇适用**：用户问"开新任务前要不要先开新对话、怎么确认真的开了新会话"

**规则**：每一个新的 `task_id` 开始前，**必须先开新会话**，再发第一条指令。

**逐软件动作与完成判据**（锚文本逐字抄自已验收档案）：

| 软件 | 按钮原文 | 完成判据（逐字） |
|---|---|---|
| 豆包 | 侧栏 `新对话`（D09） | 输入区占位变 `有什么我能帮你的吗？`；该项选中后显示快捷键 `Ctrl Shift K` |
| 元宝 | 侧栏第 1 项 `新建对话`（Y01） | 主区清空、输入区工具栏出现（主区可能纯黑，见 E-010） |
| 智谱清言 | 对话模式 `新对话` / 任务模式 `新建任务`（**同一颗按钮，文字随模式变**，Z15 / Z01） | 回到空输入区，占位按当前模式 |

**判错**：开完仍是旧会话（占位、历史消息都在）→ 说明点到了「最近」列表里的既有会话条目，不是「新建」那一颗，退回重开。

**依据**：`doubao-buttons.md` D09 / `yuanbao-buttons.md` Y01 / `zhipu-buttons.md` Z01、Z15 / `experience.md` E-010

## 二、同一任务的子任务必须复用会话

- **本篇适用**：用户问"生成剧本和拿剧本生成视频，要不要各开一个新会话"

**规则**：同一 `task_id` 下的连续步骤**必须复用同一会话**，中途不许新开。

**为什么**：第二步要吃第一步的产物。例：`生成 2 秒剧本` → `用剧本生成视频`，两步是同一任务的子任务；若在第二步前新开会话，**第一步产出的剧本文本不在上下文里**，第二步拿不到剧本。

**判据**：第二步发出前，回看当前会话里**能看到第一步的回答正文**（同一窗口、同一会话标题不变）。看不到 = 会话被换掉了，退回重做第一步。

**依据**：`PLAYBOOK.md`（豆包作文链"不新开会话就沿用当前会话"）/ `experience.md` E-057（接力喂文件务必同一会话）

## 三、任务 ID ↔ 会话 ID 显式绑定

- **本篇适用**：用户问"怎么保证指令发到了该发的那个会话里"

**规则**：派单时由调度侧把 `task_id` 与 `会话 ID`（窗口/标签标识）记成一条绑定关系；发指令前**按绑定取会话**，不许"看当前窗口开着什么就往里发"。

**判据（本机可核）**：
- 窗口标题与绑定记录一致（豆包标题会随会话变：有会话是「会话名 - 豆包」，点 `新工作任务` 后变成纯 `豆包`，见 E-021）；
- 会话内能看到上一步的产物正文。

**注意**：本库**未实测**"任务 ID ↔ 会话 ID 自动绑定"这件事——它属派单执行链（`dispatch()`）的职责，本知识库只提供判据文本，本身不产生任何动作。

**依据**：`doubao-buttons.md` D09、`experience.md` E-021

## 四、误入旧会话的恢复动作

- **本篇适用**：用户问"发现指令发进旧会话了、已经污染了上下文，怎么退"

**规则**：
1. 立刻停止在该会话继续追加指令；
2. 点侧栏 `新对话` 重开一个新会话，把本任务从头执行；
3. **不要**在原会话里追加"忽略以上内容""请忘记前面的对话"之类的补救提示词——库内没有任何实测证明这类提示词能清掉上下文。

**判据**：新会话占位回到 `有什么我能帮你的吗？`（豆包）/ 主区清空（元宝）。

**依据**：`doubao-buttons.md` D09 / `yuanbao-buttons.md` Y01；"补救提示词无效"这一条属**操作纪律**（未实测，不作事实依据）

## 五、易混按钮：这三颗都不是"开新对话"

- **本篇适用**：用户问"AI创作、新工作任务、新建任务这几个是不是开新对话"

| 按钮 | 真实后果 | 出处 |
|---|---|---|
| 元宝 `AI创作` | **进生图页，不是开新对话**（彩排事故根因，锚文本 `开始你的创作吧`） | `yuanbao-buttons.md` Y02 / `experience.md` E-001 |
| 豆包 `新工作任务` | 进任务态，窗口标题变纯 `豆包`，占位 `今天有什么工作要…`（**不是新会话**） | `doubao-buttons.md` D04 |
| 智谱 `新建任务` | 任务模式的"新会话"，**只在任务模式下等同新建**；对话模式下叫 `新对话` | `zhipu-buttons.md` Z01 |

**定位方法**：按 `generic-buttons.md`「新建对话 / 新对话 / 新建任务」那一条——**按钮文字不可靠**，用**相对位置 + 锚文本**定位（例如元宝：锚 `AI创作` 上移一行就是 `新建对话`），别按文字硬匹配。

**依据**：`generic-buttons.md`（通用按钮族·新建对话）/ `yuanbao-buttons.md` Y02 / `doubao-buttons.md` D04 / `zhipu-buttons.md` Z01

## 六、本规则的效力边界

> **本条规则必须在云端大脑的派单契约中作为强制前置动作落地；本知识库仅作参考，被动检索不会自动产生"开新会话"这个动作。**

- KB8 是**被动检索问答库**：只在聊天问答链 `provider(query) → KnowledgeRAG(KB8)` 里被读，**不进入派单执行链**（`dispatch() → /api/tasks → 本地执行器`）。
- 因此本条目**只能**提高"被问到时答得对"的概率，**不能**保证执行器真的先开了新会话。
- **不许**把本条目的交付写成"补了这条规则，会话污染就修好了"—— 修好它需要派单契约里的强制前置动作（见 v4 要求第三节 3.2）。

## 检索提示

- 开新任务前要不要先开新对话、怎么确认开对了
- 同一任务的两步能不能分开两个会话
- 指令发进旧会话了怎么退、能不能用"忽略以上内容"救
- `AI创作` / `新工作任务` / `新建任务` 是不是开新对话
- 这条规则为什么不等于"会话污染已修复"
