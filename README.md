# 咕嘎 · 会监工的 AI 管家桌宠

> 咕嘎既是桌宠，也是管家。
>
> 作为**桌宠**：一只 Q 版企鹅常驻桌面，会语音聊天、会分析游戏对局、会饿会闹有状态；
> 作为**管家**：你说一个目标，它拆成子任务、派给不同的 AI 去干、全程盯进度、按验收标准收货——不合格当场打回重做。
>
> 市面上的桌宠陪你聊天，咕嘎替你**管着所有 AI**。

**生产力 / 办公效率** · 全国人工智能应用创新大赛参赛作品 · 代码 + 可运行三端全在仓库内

## 一、它解决什么问题

现在一个人手里往往同时开着豆包、WorkBuddy、JoyCode 三个 AI。真实的工作流是这样断掉的：

1. 你要自己判断哪个任务该给哪个 AI（**不会派单**）
2. 你要自己把上下文复制过去（**不会交接**）
3. 你要自己盯着它是不是跑完了（**不会盯进度**）
4. 它给你一坨东西，你还得自己判断对不对（**不会验收**）
5. 这次怎么干成的，下次还得从头想（**不会复盘**）

三个 AI 是三个工具，不是三个员工。**缺的那个角色是"包工头"**。

咕嘎就是这个包工头。它以一只桌面宠物的形态常驻在你的屏幕上——这是它的交互外壳，也是它的存在感；它的内核是一套**任务拆解 + 智能体派单 + 进度监工 + 验收打回 + 经验沉淀**的闭环系统。

## 二、桌宠的一面：游戏军师与语音交互

咕嘎不是凭空出现的"工具人"。它先是一只活着的桌宠，管家能力长在这只桌宠身上——这一面让用户愿意把它留在桌面上，那一面让留下来变得值得。

### 游戏军师（酒馆战棋）

- **看对局**：优先读取游戏日志解析棋盘（零 API 调用、不触发限流），日志不可用时自动回退视觉模型截屏分析
- **算胜率**：蒙特卡洛模拟 n=600，后台线程执行，主界面不卡顿
- **给建议**：对手阵容流派分析 + 己方阵容方向规划，配战棋知识库（`knowledge/battlegrounds/`）
- **战绩记忆**：最近对局历史留档，复盘有据可查
- 代码：`core/log_reader.py`、`core/battle_sim.py`、`core/comp_analysis.py`、`core/lineup_planner.py`；棋盘解析依赖 `lib/` 内第三方只读库（许可见 `THIRD_PARTY_NOTICES.md`）

### 语音交互

- **按键说话**：按住说话、松开即答，回答自动 TTS 朗读
- **持续语音对话**：流式收音、边听边播、语音打断、断线续接（`core/realtime_voice.py`）
- **音色**：edge-tts 软萌音（`ui/tts_engine.py`），异常时豆包语音兜底
- **事务播报**：管家派的活有进度变化时，桌宠用语音主动播报——这条语音链路同时服务于两个身份

## 三、管家的一面：四个核心创新

### 1. 监工引擎：把"人管 AI"变成"AI 替你管 AI"

这是本作品与所有桌宠类产品的分界线。市面桌宠的核心是**情绪陪伴**，咕嘎的核心是**任务闭环**：

| 环节       | 具体做法                                    | 代码位置                           |
| -------- | --------------------------------------- | ------------------------------ |
| 任务台账     | 每条子任务有状态机：待派 → 进行中 → 待验收 → 完成 / 超时 / 打回 | `cloud/server.js` · 台账接口       |
| 派单时定验收标准 | 拆解阶段就写死"这条怎么算完成"，不做事后扯皮                 | `cloud/knowledge/supervision/` |
| 进度盯梢     | 轮询执行方心跳与步骤回执，桌面端头顶显示进度状态                | `agent/guga_agent.py`          |
| 验收把关     | 交付物按预设标准逐项核对，不合格**自动打回重做**              | `cloud/server.js` · 验收链        |
| 证据留痕     | 执行本体每一步截屏取证，回传证据墙，评委可逐帧复核               | `agent/guga_executor.py`       |

**关键设计**：验收标准在派单时确定，而不是交付后由 AI 自己判"我觉得挺好"。这是"监工"和"自嗨"的区别。

### 2. AI 指挥 AI：真的把活派给别的 AI

咕嘎不假装自己什么都会。它有一张**智能体注册表**，按任务类型选执行者：

- **本地工作流**：文件整理、定时提醒、习惯记录（桌宠本体直接干）
- **云端大模型**：拆解、验收核对、生成汇报（`cloud/server.js` 调 LLM）
- **外部 AI 软件**：把任务真的派到本机的豆包 / WorkBuddy / JoyCode 上，让它们干活（`apps/*.json` 声明式适配 + 界面自动化执行）

第三条是硬骨头，也是本作品工程量最大的部分。

> 为什么派活走界面自动化、而不是要求用户给每个软件配 MCP 后由咕嘎调用：**MCP 只负责"发现"（软件自报身份与安装路径），"指挥"仍然靠界面自动化（视觉 + UIA）**。详见 [docs/MCP与界面自动化.md](docs/MCP与界面自动化.md)。

### 3. 真机执行：不是演示动画，是真的在你电脑上点

`agent/guga_executor.py`（约 1200 行）解决的是"让 AI 在真实桌面环境里可靠地操作别的 AI 软件"这一堆脏活：

| 工程难题         | 真实表现                              | 解法                                       |
| ------------ | --------------------------------- | ---------------------------------------- |
| 跨分辨率失效       | 本机 100% 缩放正常，演示机 150% 就点偏         | DPI 感知提前到所有第三方库导入之前，并以系统读回值为准（不谎报成功）     |
| 4K 屏视觉认不出按钮  | 固定 800px 送模型，满屏正文只剩 2.9px         | 送模型图宽自适应 800→1600，并做两级区域放大定位兜底           |
| 托盘隐藏误判"软件没开" | 点关闭后进程还在、窗口变隐藏，`pygetwindow` 枚举不到 | 主动唤醒托盘，实测 4/4 成功                         |
| 截图截到别人的窗口    | 多款 AI 桌面端窗口几乎完全重叠，截 A 截出 B          | 强制置前 + 句柄校验                              |
| Windows 前台锁定 | `SetForegroundWindow` 静默拒绝，4/4 失败 | 先注入一次 Alt 伪造用户输入，4/4 一次成功                |
| 安装路径不可猜      | 三款软件默认路径全错、注册表也没登记                | 进程反查 exe 路径，4/4 命中并排除 CrashHandler 等附属进程 |
| 长任务失控        | 死循环、越权操作                          | 鼠标甩左上角紧急停手（FAILSAFE）+ 剪贴板进出还原 + 新对话隔离    |

这些不是设计文档里的假设，是 2026-11-05 真机联调中逐条复现、逐条修掉并留档的（见 `cloud/docs/多软件真机联调-20261105.md`，`agent/preflight.py` 上线体检 **18 项 / 0 FAIL**）。

### 4. 复盘沉淀：同样的活第二次更快

任务成功后，执行链会被抽象成"经验候选"，经人工审核进入技能库。下次同类任务直接命中已验证路径，不再从零拆解。

## 四、系统架构

```
┌─────────────────────────────────────────────────────────────┐
│  ① 桌宠端  ui/ + core/  （PyQt5 · 24,000+ 行）              │
│     形象表现 · 语音交互 · 游戏军师 · 本地工作流 · 任务呈现   │
│     ☁️ 监工客户端：说目标→云端拆解派单→台账面板→验收播报     │
│        （core/butler_cloud.py + ui/task_panel.py，合一入口） │
│     🤖 内嵌执行方：自动配对·领单·指挥本机AI（core/local_agent.py）│
└───────────────────────┬─────────────────────────────────────┘
                        │ 用户说：把本周实验数据整理成周报
┌───────────────────────▼─────────────────────────────────────┐
│  ② 云端大脑  cloud/  （Node.js · 2,187 行 + 前端 1,460 行）  │
│     目标 → 子任务拆解（含验收标准）                          │
│     智能体派单 → 任务台账 → 进度轮询 → 验收打回 → 证据墙     │
└───────────────────────┬─────────────────────────────────────┘
                        │ 派单（配对码绑定设备，不用公网 IP）
┌───────────────────────▼─────────────────────────────────────┐
│  ③ 真机执行本体  agent/  （Python · 2,286 行）              │
│     领单 · 唤醒并置前目标软件 · 视觉定位 · 输入 · 取回答案   │
│     全程截屏取证 · 每一步画面校验 · 不合格按异常分支停手     │
└───────────────────────┬─────────────────────────────────────┘
                        │ 真实鼠标键盘
                 ┌──────▼──────┐
                 │豆包/WorkBuddy│   这些是你本来就在用的 AI
                 │/JoyCode    │   咕嘎不替代它们，指挥它们
                 └─────────────┘
```

**三端为什么要分开**：桌宠要好看、要常驻、要能碰你的本地文件；云端要做长任务调度、要能被多看几眼；执行本体要装在你自己的电脑上才有权限。合成一个进程，三件事都做不好。

**但用户界面只有一个——桌宠，而且执行端也内嵌在桌宠里。** 桌宠内置监工客户端（`core/butler_cloud.py`）：对它说一句目标，云端大脑负责拆解与验收裁决；桌宠登录后自动把自己注册为执行设备（`core/local_agent.py`，进程内自动配对，无需配对码），派给本机的子任务由桌宠自己领单、自己指挥本机 AI 软件完成（复用 `agent/guga_executor.py` 全套视觉定位与取证能力）。任务台账面板（`ui/task_panel.py`）在桌宠旁展开"监工现场"。同一账号在任何设备登录，看到的是同一份台账——跨设备协同天然成立。Web 端退居为可选的远程查看后台；独立值守程序（`agent/guga_agent.py`）仅在"另一台电脑当执行机"时才需要。

**它怎么认出你电脑上的 AI 软件**：发现与指挥是两件事。发现按「用户手动指定 > 软件通过咕嘎 MCP 自报 exe 绝对路径 > 声明清单 + 注册表/开始菜单/常见目录/PATH/进程探测兜底」逐级取路径；指挥一律走界面自动化（视觉 + UIA），MCP 不派单。识别成功但未登录、白屏或停在编辑页时，派单阶段会带失败码和下一步提示回报，不会假装完成。完整机制、实测耗时与"声明/实现不一致清单"见 [docs/软件识别机制.md](docs/软件识别机制.md)。

## 六、快速运行

### B. 在线体验（最快，零安装）

浏览器打开在线体验端，用演示账号登录，直接对咕嘎说一句话派个任务：

```
地址：http://39.107.48.60:3000
```

> 在线端跑的是云端大脑，能看到完整的任务拆解 → 派单 → 台账 → 验收流程。  
> 若需验证"真机执行"环节，请按 C 步骤在本机启动执行本体（需本机装有目标 AI 软件）。

### A. 下载 exe 直接跑（免装 Python，推荐评委用）

到本仓库的 **Releases** 页下载最新的 `GUGA-Desktop-win64.zip`（约 347MB，解压后约 610MB，Windows 10 1809+ / 11 x64）：

1. 解压到任意目录（只读目录也可以；保持 `GUGA-Desktop.exe` 与 `_internal\` 在一起，不要只拷 exe）
2. 双击 `GUGA-Desktop.exe`——先过启动自检（12 项，致命/降级分级），再进首次配置向导（选平台、填 API Key、当场测通）
3. 配置写在用户可写目录 `%LOCALAPPDATA%\GUGA\ai_config.json`（包内不带 Key；旧版放在安装目录的配置会自动迁移），填完企鹅出现在桌面

> 未签名程序首次运行需在 SmartScreen 点「更多信息 → 仍要运行」。
> 完整系统要求、安装步骤、各功能需要装什么、已知限制见 [INSTALL.md](INSTALL.md) 与 [USAGE.md](USAGE.md)。
> `%LOCALAPPDATA%\GUGA\ai_config.json` 含 API Key，请勿外传；仓库内不带任何真实凭据。

### C. 源码启动桌宠

```powershell
pip install -r requirements.txt
copy ai_config.example.json ai_config.json   # 填入你的对话 API
python comp_main.py                          # 参赛版：管家形态
python launcher.py                           # 开发版：完整能力
```

需要 Windows 10/11 + Python 3.10+（推荐 3.12）。

启动后的常用入口：**数字键 1** 请教助教（截屏看你的屏幕再回答）· **数字键 2** 助教出题 · **数字键 3** 语音对话 · 右键菜单可打开战棋对局分析与实时语音配置。

**打开管家监工（合一的关键一步）**：在 `ai_config.json` 里加 `cloud` 段（见 `ai_config.example.json`），填云端大脑地址与账号，重启桌宠后右键菜单多出两项——**🗣️ 派个任务…**（说目标即派单）与 **📋 任务台账**（监工现场面板）。验收通过与打回会由桌宠语音播报。

### D. 真机执行（已内嵌进桌宠，通常无需单独启动）

派给本机的子任务由桌宠进程内的执行方直接完成——桌宠登录云端账号后**自动配对**（进程内自动生成并兑换配对码，用户无感），心跳领单后调用 `agent/guga_executor.py` 的视觉定位与窗口管理能力，指挥本机 AI 软件干活，全程截图取证回传证据墙。鼠标甩到屏幕左上角可随时紧急停手。

如需把另一台电脑单独作为执行机（那台不装桌宠），才用独立值守方式：

```powershell
cd agent
pip install -r requirements.txt
python preflight.py             # 先体检：18 项，确认本机能不能真机干活
python guga_agent.py <配对码>    # 配对码在云端 Web 端"自检"弹窗生成
```

### E. 自建云端

```powershell
cd cloud
copy .env.example .env          # 填 LLM_API_KEY；不设 JUDGE_PASS 会启动时随机生成
npm install
npm start
```

## 八、安全与合规

- **可撤销**：每个执行步骤留痕（截图 + 动作 + 结果），任务完成可导出证据包复核
- **不破坏**：只做读与操作，不做持久化写入；执行前保存剪贴板、执行后还原
- **不污染**：新对话隔离，绝不动用户已有的会话与画布任务
- **隐私下线**：微信 / 企业微信 / QQ 三款因隐私风险主动从支持列表移除
- **凭据不入库**：所有 API Key 走 `.env` / `ai_config.json`，已在 `.gitignore` 中屏蔽
- **素材原创**：角色形象 100% 原创 Q 版企鹅，不使用任何商业 IP 或第三方模型二创；桌宠窗口、Web 端、任务面板三处共用同一套形象素材（`resources/expressions/` 与 `resources/actions/`），不出现"同一个作品两个角色"的割裂
